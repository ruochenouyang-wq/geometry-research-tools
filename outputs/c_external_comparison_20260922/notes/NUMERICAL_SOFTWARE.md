# C1/C2 与成熟特征值软件：比较对象和验收边界

核对日期：2026-09-22。本文读取公开 C2 报告及候选构造代码，实际查阅下列三项官方文档；未安装、导入或运行外部数学软件，未修改算法。

## 先定义术语

**离散化**是用有限个自由度表达原来的函数问题。本项目的候选系数满足广义特征值问题 `Hc=λMc`；`H` 是能量矩阵，`M` 是质量矩阵，用来表示函数大小。实对称且 `M` 正定时，可使用对称广义特征值算法。

**矩阵残差**是 `Hc−μMc`；它只反映该有限矩阵方程。**完整函数残差**是把对应试函数代入原算子后得到的误差，必须包含候选空间外的部分。两者不能互换。

**移位逆变换**把求解转为反复使用 `(H−σM)⁻¹M`，其中 `σ` 是选定移位。**停止阈值**规定误差估计足够小时结束计算；阈值对应哪个问题、哪种范数，必须写明。**谱隙**是目标谱值与其他谱值的间隔，本项目的 Temple 认证需要相邻谱值的严格下界。

上述版本是本轮网页显示值，不是本机安装版本。`eigh` 不自动检查输入是否对称，`M` 必须满足正定条件；输入检查和病态情况须纳入对照。[SciPy `eigh` 的输入与错误说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.linalg.eigh.html)

**结论：按残差停止、改变迭代空间和移位逆迭代，已有成熟实现。** C1/C2 的可评估差异应是“将完整原题的认证目标反馈给计算预算，以及它在指定任务上是否有净收益”，不能仅凭这些机制宣称新数学算法。

## 数值收敛与原题认证相隔哪些步骤

以下是结合项目证书结构作出的分析：

1. 浮点求解得到的是近似矩阵和近似向量；把矩阵残差算得很小，不会自动补偿积分、舍入、表示截断或未覆盖角向分量的误差。
2. SLEPc 的 `true residual` 指未作谱变换的**矩阵方程**残差；仍不是本项目无限维函数问题的完整残差。
3. 有限矩阵中两个特征值相隔很远，不足以证明原算子的第二谱值下界 `β`。在缺少这一证明时，不能把数值第二特征值直接代入 Temple 公式。
4. 本项目若继续用精确积分重算候选的 Rayleigh 值与完整残差，并保留已证谱隙和全部空间覆盖，外部浮点求解器可以只负责产生候选。最终证书能否通过，依然由同一验收器决定。

因此，应分别报告有限矩阵求解质量、原题认证宽度与总成本；只报告多次加密后小数一致，不能替代原题误差证明。

## 奇异势和界面需要的适配

这部分是针对当前球面模型的推断，而非声称三个软件开箱即支持该原题：

- `q=b+a|z|^α` 的奇异位置在赤道；分成半球区间后成为界面端点。候选应具有适当的局部幂行为，积分应处理不可直接采样的奇异点。把该点的无穷值任意截断会改变所计算的模型。
- 阶跃势的两侧候选要满足原问题要求的拼接条件；采用强残差时，不能遗漏导数跳跃产生的分布项。
- 零均值约束、球面极点的正则性、质量内积和各角向分量必须保持一致。小矩阵近似最小值若属于错误分量，额外求解精度不能修复任务绑定。
- 分数幂基的质量矩阵可能数值病态。双方应允许相同的合法缩放、消去或正交化，并记录相关成本。浮点求解失败应保留为失败，不能临时换弱题。
- 当前强残差路线在 `α=-1/2` 处会遇到平方势矩的可积性障碍；这不是所有弱形式或原算子都失效。若改用另一种离散化与误差理论，须作为新的完整方法单独比较。

## 本机最值得先复现的对照

**建议优先 `scipy.linalg.eigh(H_float, M_float, subset_by_index=[0,0], driver='gvx')`。** 这是基于当前候选矩阵规模较小、稠密、实对称的适配判断，没有预设它更快。根任务另行核实本机 SciPy 与底层 LAPACK/BLAS 版本。

第一组比较只替换候选器：使用完全相同的原题、候选幂、变换后的 `H/M`、严格谱界及证书验收。外部向量按预先固定规则转成有理数，重算全部原题证据；不能把浮点特征值包装成有理数就算认证。将其命名为“SciPy 候选器＋本项目认证”，避免误称独立外部全局证明。

还须区分候选器的优化目标：`eigh` 求候选空间内的最小 Rayleigh 值，而 C2 还尝试改善完整残差；前者未必使最终 Temple 区间最窄。应单列“有限矩阵已解好、完整残差仍过大”的失败。如果双方共享后续残差修正，该共享步骤也要写进系统名称与计时。

第二组再比较控制策略：相同的候选器分别使用预先固定的次数计划和 C1/C2 的按需策略。这样才能区分收益来自成熟矩阵算法、表示选择还是预算控制。若改用外部有限元或谱离散化，则积分、表示、误差理论都改变，属于另一组完整流程实验。

公平比较须预先固定原题与精度，允许双方合理的缩放及已证移位信息，并固定候选计划或明确谁负责选择。记录冷启动、矩阵装配、变换、求解、全部失败尝试、原题认证和输出成本；记录线程数、硬件、内存及软件版本。双方共同达标题比较时间，失败与超时另外计成功率；数值答案和严格证书采用不同结论标签。若外部方法缺少原题认证，应报告这个能力差异，不能把较弱完成条件下的速度直接解释为优劣。

本轮没有运行这些对照，故没有外部速度、成功率或模型 token 结论。
