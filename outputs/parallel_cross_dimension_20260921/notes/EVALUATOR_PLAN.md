# 独立评估器设计草案（待题单与接口确认）

仅复用旧 `geometry_parallel_v1_20260921/evaluation/compare.py` 的父进程监督、固定分母、证书重放和身份核对思路；不导入或执行旧文件，不改旧源码。新实现拟写在本目录 `benchmark.py` 与 `selftest.py`。当前只写设计，未运行性能实验。

## 接口和任务绑定

题单提供 `{id, stratum, task}`；`stratum` 标明研究维度和任务族，仅用于分层汇总。三算法接收同一份不可变 `task`，原函数、空间/维度、目标量、容差和预算全部进入规范 JSON 哈希。不得在适配器里偷偷放宽容差或换成更简单的题。暂定 `solve(task)->result`、`verify(certificate, task)->verdict`；结果含完整证书、实际路线、是否回退及原因、全部尝试。评估器自身核对题意绑定、精确有理误差和目标达成，不信任 solver 的成功状态。

批量接口可选 `prepare_batch(tasks, limits)->context` 与 `context.solve(task)`；准备应明确仅收到题单/家族规格，不收到答案。普通方法可使用空准备包装。A/B 真正路线和 B 家族规格由根确认后固定；各路线内部缓存与离线准备全部披露。若任务不支持而回退，结果保留，另报真正路线成功数。

## 单题与同会话两种口径

单题为全新 Python 进程，预算从父进程启动前开始，覆盖导入、准备、求解、JSON 编解码、完整验证和原始落盘。给出整进程费用及可相加的准备/求解/编码/验证细分；内层重叠的自报耗时不得相加替代外部总计。

同会话运行固定题序、一次准备、多次查询；每算法均使用同样会话口径。报告首题、后续题、累计 N 题和准备摊销，但比较主表始终包含真实准备费用。批量中每个证书都须独立完整验证；缓存上下文的快速检查不能冒充完整重放。可沿用旧评估器的做法：会话内完成检查和输出，会话结束后每张证书再用全新进程完整重放，另列冷重放费用，同时提供含其费用的严格总账。批量准备失败或硬截止后未执行的题按失败保留，发生的成本仍计入固定分母。

每个模式固定五次重复，按题/重复交错轮换三算法，始终串行。批量会话顺序也轮换；题序可在重复间按预定规则变化，同一重复的三个系统完全一致。不把 B 温态对 A/C 冷态，不挑成功重复或只报最快一次。

## 资源和完整验证

记录父测 wall、系统 user+system CPU、进程 peak RSS、规范 UTF-8 输出 JSON bytes、证书 JSON bytes、完整验证 wall/CPU/RSS。macOS 的 `ru_maxrss` 单位为 bytes，记录平台和原始单位，不能误乘 1024。建议父进程用 `os.wait4` 获取每个子进程的独立 rusage，包括被杀进程；不可对 `RUSAGE_CHILDREN.ru_maxrss` 做前后相减。监督时避免 `Popen.poll/wait` 提前回收子进程而丢失 wait4 统计。

同会话 RSS 是整个进程的累计高水位，不能相减伪装为单题峰值；另报会话峰值和每个时点已观察高水位。冷重放单独进程给自己的峰值。串行进程峰值可取最大，不能把峰值求和当同时内存。若未来实现自行创建子进程，需扩充进程树计量，当前数字明确称“被测进程峰值”。输出字节与证书字节是序列化体积，不是 token；不调用模型 API，实际开发/推理 token、缓存 token 均未知。

## 截止、证据、汇总

父进程根据预先固定的全局绝对截止和批量阶段截止杀死整个进程组；子进程报阶段完成不能延长全局期限。验证和落盘仍在相应期限内。若额外冷重放另设预算，必须同时公开它与附加费用，不能宣称最初截止已覆盖两个进程。SIGALRM 只作合作退出，不能替代父硬截止；测试覆盖吞异常、无限循环、导入/验证/写盘卡住。

开始前冻结三入口、适配器、完整可达依赖、评估器、协议和题单，保存源码快照；结束后全部重算哈希。代码/任务变化的运行保存但不计作有效冻结比较。每条记录保留 case/method/repeat/mode、原题哈希、完整结果、独立验证结果、超时/崩溃/未执行原因和资源值；损坏或缺失 JSON 也生成失败行。

先报各层 5/5 稳定认证数和错误接受，再在相同成功且相同真实路线条件下比较五次原始值、中位数、范围、配对 wall/CPU 比率、RSS 和证书体积。总体成功率不得混合不同目标量；失败的耗时仍进总资源账，失败/成功费用分列。不用五次重复宣称普遍加速，也不把常势校准当数学新能力。
