# v238–v317：80 轮改进与验收报告

日期：2026 年 9 月 19 日。依据：[数学研究工具长期指导报告 1.1](../geometry_research_strategy/研究指导报告.md)。

## 1. 本轮完成了什么，尚未证明什么

80 轮实际改动已经实现，组成可运行的本地数学研究工具。每轮均保存当时的源码、改动假设、检查与对照；另外记录了将组件接合时发现的问题及修复。历史 1,139 个文件未改变。最终实现通过 197 项测试，其中包含 22 项独立数学检查。之前固定的旧版 98 项测试也全部通过。

本轮有明确的局部收益：相同数学证书的三个计算部件约快 1.26–2.01 倍；一个固定谱界约收紧 4.81 倍；同样的函数逼近精度可以使用更小表示；多个奇异指数可以自动生成候选并认证。**这些结果不等于所有输入、所有指标都进步。** 最终留出题上，新旧方法均完成 6/6，新方法仍慢于简单的固定递增策略。当前证据不满足“各维度全面胜出”的强解释。

这里的**留出题**指开发者在实现冻结前不查看具体实例、只在冻结后用于评价的题。该组只有六题，覆盖已知函数族的新参数，不能代表广泛数学研究能力。**模型 token**是模型处理文本的计量单位；本轮只测量部分可见交互文本的离线编码长度，没有测量真实模型的输入、输出或隐藏推理消耗。“较低成本模型半小时胜过较强模型八小时”仍是未验证的长期目标。

## 2. 报告原则怎样变成了算法

新系统把研究过程分为五个连续步骤：先确定原题与完成标准，再产生候选，对候选进行数学检查，依据检查结果选择下一步，最后保存可以复查的证据。

目前有两类不同目标。**函数逼近**用较简单的分段多项式代替原函数，并计算两者的整体误差；这里的 **L² 误差**是函数之差平方的平均值再开平方。**谱估计**计算某个能量问题的最低值所在区间；上界减下界是区间宽度。前者误差为零，不能自动推出后者已解。系统因此要求明确目标，分别检查。

**候选**只是值得检查的函数或计算方案，不能凭生成它的程序自称成功。**证书**保存原题、上下界及复查需要的数据；**验证器**重新检查这些数据。系统分别报告证书有效、达到目标精度、在预算内返回三件事。超时后的正确证书可以保留，但不计作预算内完成。

在表示选择方面，程序分别估计靠近奇异点的误差、其他分段的误差以及数值取整带来的余量，再调整多项式次数、分区层数和取整精度。在谱任务中，**残差**衡量候选偏离所需方程的程度；程序区分可通过调整系数减小的部分和需要更换表示才能减小的部分。不过，这种诊断仍是选择动作的依据，不是保证下一步改善的定理。

程序还能按已经证明的规则复用常数平移、坐标轴改变等结论。证据按完整内容保存并检查是否被修改；研究关系只有在对应条件实际成立时才获认证。一般性的“等价”“能推出”关系没有默认认证规则。

## 3. 七个维度的证据与边界

| 维度 | 本轮可核验改变 | 必须保留的限制 |
|---|---|---|
| 精度与表示大小 | 同一候选的谱区间从约 `1.87189e-8` 收紧至 `3.88892e-9`，约 4.81 倍；一次额外残差优化后为 `3.26250e-10`。函数逼近目标 `1e-8` 的展开系数位置数由先前高精度设置的 1009 降至 749 | 收紧区间的倍数不是提速倍数；749 是配置的有限模型族中按系数位置数选择的结果，不是所有可能函数中的全局最优 |
| 可靠性与原题覆盖 | 无效参数在计算前拒绝；原函数、空间和目标绑定；完整残差与遗漏部分继续计入；最终 28 次错误证据探针均拒绝，独立数学检查 22 项通过 | 检查程序仍需被信任；没有形式化证明助手逐步核验全部定理，也不能靠有限测试证明没有错误 |
| 自动研究动作 | 自动选择逼近配置，区分误差来源，在普通谱与奇异谱路线间比较；公开低精度开发题暴露的过度计算已改为先试便宜路线 | 留出成功数没有超过三种基线；自动调度仍有开销，不能称为已经优于所有简单策略 |
| 新参数适用性 | 原先固定 `-\|z\|^(-1/4)` 的高精度候选方法扩展到受支持的其他负有理指数；已知开发参数 `-1/8` 和 `-1/3` 分别达到约 `4.19e-13`、`2.50e-11` 的谱宽 | 是单个精确参数点的认证，须满足方法的稳定性条件；留出只测试已有函数族的新参数，没有测试新几何或新数学结构 |
| 运算效率 | 固定矩计算从 540 次调用变为 17 个唯一矩；四点评估所需完整证书检查从 4 次变为 1 次；同结果串行探针约快 1.26–2.01 倍 | 自动研究在最终六题上仍慢于固定递增；冷启动、复用准备及实际任务难度影响收益 |
| 交互文本与成本 | 保存完整证据、摘要按需取回，记录失败与补读成本；12 次预定交互相对合理精简摘要减少约 2.85% / 3.47% 的可见编码长度 | 单次请求没有节省；大量补读会显著稀释百分比；未测试模型理解率或真实推理消耗 |
| 可用性与复现 | 一个入口提供自动任务、摘要/完整视图、批处理、证据读取和验证；错误不影响后续请求；197 项最终测试通过 | 仍是本地程序工具，没有真实新手使用实验；早期快照复跑暴露过相对文件路径及解释器依赖问题，记录保留 |

**矩**在这里指函数与不同幂次相乘后的积分值，是后续矩阵计算反复使用的原材料。**系数位置数**衡量表示展开后需要存放多少个多项式系数，不等于内存峰值或 token 数。所谓原题的“全局”谱界，是界限覆盖规定的完整函数空间；它不意味着程序已经找到最优研究策略。

精度和扩展结果见 [奇异谱记录](SINGULAR_NOTES.md)、[自动逼近记录](APPROX_NOTES.md)。效率及适用条件见 [精确计算记录](FAST_MATH_NOTES.md)、[同结果性能原始数据](metrics/equivalent_benchmark.json)。

## 4. 最终留出比较：没有隐藏简单基线

**基线**是用来比较的已有方法。本轮保留三种：旧默认配置、按事先固定顺序逐步增加计算量、在另外五道验证题上选择一个统一固定配置。最后一种的准备成本也计入。没有为每道留出题事后挑选最好的参数。

最终代码、评测规则和固定配置选择先写入 [冻结清单](evaluation/freeze_manifest.json)，随后才生成六道留出题。生成前只保存随机种子的公开承诺值，即可以事后核对的哈希；没有提前查看种子或实例。**哈希**是用于核对内容身份的摘要，不是数学证明。实现冻结后未根据留出答案修改算法。

| 方法 | 达标题数 | 总计 CPU 时间（秒） | 错误证据被接受 |
|---|---:|---:|---:|
| 旧默认 | 6/6 | 0.272735 | 0/7 |
| 固定递增 | 6/6 | **0.013863** | 0/7 |
| 验证集选择的固定配置 | 6/6 | 0.134739 | 0/7 |
| 本轮新服务 | 6/6 | 0.022538 | 0/7 |

**CPU 时间**是进程实际占用处理器的时间，区别于人等待的墙钟时间。表中计入求解、证据重放、错误证据检查以及适用的配置选择准备。新服务总墙钟约 0.02668 秒。它是同一进程中按题交错执行的一次小样本评测，模块的延迟加载可能进入各方法的首次调用；不是独占机器、严格统一冷启动的性能实验。

新服务相对固定递增的 CPU 时间约多 63%，因此不能只展示与较慢旧默认的比较来声称整个系统提速。该组的成功率没有提高，也未满足相对最快同成功率基线减少 20% 成本的强验收要求。它证明了这六题的适用性和检查通过，尚未证明泛化优势。常数题得到精确界属于正确使用特殊公式，不能冒充解决难题。

全部请求、返回、失败分支、选择成本和独立验收见 [最终留出原始报告](evaluation/holdout_comparison_20260918T193409761871Z.json)；开发及验证结果由 `evaluation/latest_development.json`、`evaluation/latest_validation.json` 指向。完整方案见 [评测协议](EVALUATION_PROTOCOL.md)。

## 5. 真实高精度检查与保留的失败

以下均为已知开发检查，不能再称作留出题。这里 `z` 是单位球面的高度坐标，谱任务均采用平均值为零的函数空间，目标宽度为 `1e-8`。

| 原题 | 结果 |
|---|---:|
| `-\|z\|^(-1/4)` 的函数逼近 | L² 误差界约 `9.93532e-9`，达标 |
| `-\|z\|^(-1/4)` 的最低谱值 | 宽度约 `2.09496e-11`，达标 |
| `-\|z\|^(-1/8)` 的最低谱值 | 宽度约 `4.18995e-13`，达标 |
| `-(1/2)\|z\|^(-1/3)` 的最低谱值 | 宽度约 `2.50430e-11`，达标 |
| 负阶跃势的最低谱值 | 宽度约 `1.04031e-4`，8 次调用后仍未达标 |

所有结果均通过原题绑定检查，保留于 [完整接口检查](metrics/integrated_challenges.json)。函数逼近行不具有谱结论。

另一个重要失败是指数 `-3/8`、幅度 `-1/2` 的谱例子：候选本身的残差已很小，但其他对称部分的下界仍过粗，最终完整区间宽度约 0.04388。这说明只把候选逼得更近，不一定改善整个问题的下界。下一步应加强限制最终界的那一部分，而非继续堆候选精度。

残差驱动的贪心增项有时比固定嵌套增项更慢且更不准；正交化也有未获收益的情况。因此它们保留为可选实验方式，未当作默认必胜方法。交互中只增加请求哈希、却未删除证据位置里的重复哈希，也会增加文本量。这些负结果均见 [80 轮逐项索引](ITERATIONS.md)。

## 6. token 与整体研发成本怎么理解

交互实验使用两个公开文本编码方案 `o200k_base`、`cl100k_base`；**编码方案**规定如何把文本切分为计数单元，这里未将其映射到任何特定当前模型。每个场景计入说明、格式、请求、返回以及补读证据，比较对象是已经合理精简的摘要。

| 场景 | 原精简策略：两种编码计数 | 新策略：两种编码计数 |
|---|---:|---:|
| 单次、无补读 | 308 / 305 | 308 / 305 |
| 12 次、无补读 | 5922 / 5878 | 5753 / 5674 |
| 12 次、每次补读 | 66490 / 65666 | 66321 / 65462 |

这是预定脚本交互，不是模型自主做题。完整文本和精确计数见 [交互实验](iterations/v317/TOKEN_COMPARISON.json)。统一运行环境下的重新计数与原结果一致；[运行时修复](INTERACTION_INTEGRATION.md)说明了本机不同 Python 版本的兼容处理。

本轮使用多个 agent 并行开发、审查和评测，未超过授权的 18 个。agent 是执行独立子任务的模型协作者。开发中有三个代理会话出现连接故障；保留已落盘工作，必要时由新代理或主任务继续核对。测试脚本自身没有调用外部模型，但这不等于整个研发过程没有消耗模型 token。

目前没有完整、可按代理拆分的研发 token、重试费用、人工投入、峰值内存或真实跨模型做题账单。它们记为未知，不能用运行几毫秒的本地工具成本替代。固定配置的选择成本已经记入该基线；算法设计和开发成本没有被伪装成零。

## 7. 怎样使用和继续验收

可运行入口是 [research_service.py](research_service.py)，完整请求示例、字段解释和命令见 [使用指南](TOOL_GUIDE.md)。初次使用建议先请求自动函数逼近或谱任务，再同时查看 `certificate_valid`、`target_met` 和 `within_budget`。

逐轮记录见 [ITERATIONS.md](ITERATIONS.md)，接合修复见 [INTEGRATION_NOTES.md](INTEGRATION_NOTES.md)，最终测试见 [FINAL_TESTS.log](FINAL_TESTS.log)。80 轮快照也已各自复跑：70 轮直接通过，另 10 轮先因历史测试的相对文件路径失败，恢复原目录结构并使用原开发解释器后全部通过。原始失败与补跑结果分别保存在 `SNAPSHOT_REPLAY.json`、`SNAPSHOT_REPLAY_PORTABLE.json`，没有修改快照。跨轮重复测试不能当作更多独立测试。证据追踪审计只证明版本与文件的对应关系；数学正确性检查和效果评价另外报告，三者不能互相替代。

80 轮实现阶段已经完成。就“各个维度都有进步”的目标而言，当前可确认的是表中限定条件内的组件收益；自动调度相对简单策略的成本、广泛留出收益和真实模型表现仍有缺口。后续若依据这次留出结果修改策略，必须把这六题划为开发数据，另设新协议和未使用的留出题，不能在原题上反复优化后继续称作独立验收。
