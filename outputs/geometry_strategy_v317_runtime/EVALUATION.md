# 冷启动修订的预先公开评测

这是新的 `geometry_runtime_preregistered_v3` 评测。上一修订与 v317 原目录均保持冻结。旧六题和上一修订已经公开的十四题现在都只能作为公开回归；旧私有种子不读取。本次只生成新种子及公开承诺，在代码和协议冻结、主任务明确放行之后才允许第一次读取新种子并生成新题。

## 方法与公平比较

| 方法 | 含义 |
|---|---|
| `old_default` | 最早冻结工具默认配置 |
| `fixed_increasing` | 原 small、medium、large 顺序，独立认证达标才停止 |
| `validation_selected_fixed` | 三个同样配置在公开 13 题上各重复五次，选一个统一配置 |
| `frozen_v317` | 冻结 v317 服务 |
| `first_release` | 上一已冻结修订 `geometry_strategy_v317_release/release_service.py` |
| `release` | 本目录冷启动修订服务 |

六方法分别使用独立冷 Python 进程，五次重复。每轮固定轮换方法和题目顺序；所有方法同题同预算。一个进程只加载一种 release 版本：删除另一版目录搜索入口，检查实际模块文件身份，并拒绝已有跨版本同名模块污染。每个 session 保存实际实现路径及已加载 release 模块路径。临时证据目录和 `cache=False` 避免写入旧目录；session 内原有缓存允许，重复之间不共享。

所有数学导入、服务构造计入初始化，首次延迟导入计入首题。完整进程墙钟和 CPU 另包含解释器启动、序列化、输出、错误探针、异常及退出成本。保存五次原始值、中位数、最小值、最大值及总和，不只给在线时间。验证选择全部十五个进程的费用向该固定配置计入一次，全部失败分支保留。共享机器上可能有其他短正确性检查；这些描述性计时不宣称统计显著。

## 题目、独立性与失败

公开 13 题验证集和原配置不变。包含精确常数、容易谱、负幂困难谱、平均零与全空间、已知失败 `-3/8` 和负阶跃谱、固定 `-1/4` 在 `1e-6` 至 `1e-10` 的函数逼近回归，以及其他负指数逼近的支持边界。

新抽样仍严格使用上一公开的十四题规则：四道容易/精确题，六道负幂谱（`1e-6`、`1e-8`、`1e-10` 各含平均零和全空间），三道其他负指数函数逼近，同样三个精度，以及一道困难负阶跃谱。参数池和 SHA-256 计数抽样规则完整公开在 [protocol.json](evaluation/protocol.json)。不因不支持、稳定界不可用、未达标或超时删除或重抽题；固定 `-1/4` 永远只算回归。

相同离散池可能抽到已经公开的具体题。因此在放行后，将原任务的函数、种类、空间、容差完整规范 JSON 与 [known_public_tasks.json](evaluation/known_public_tasks.json) 比较。重合题保留，明确列出原来源与题号，标记为公开回归；同一批次的重复题也保留并标明先前题号。只有不与公开任务重合且批次内唯一的实例可算独立新实例，不能把全部十四道抽样默认称作十四道陌生题。

报告单列真正新实例的题目、稳定成功、各次成功及每次/合计在线墙钟与 CPU。整 session 的启动、初始化、探针和输出费用不能按题拆分，所以只在整 session 保留完整成本，不虚构“新实例完整冷成本”。数学适用性始终只限已知数学族内的新参数，不代表新数学结构泛化。

## 预算与可信验收

容易题总期限 3 秒，困难题 10 秒，求解、选择、完整序列化和独立原题重放共同使用这一期限。固定递增所有分支共用期限。Unix 主线程 `SIGALRM` 必须生效，超时继承 `BaseException`，不能被 `except Exception` 吞掉。另设父进程 watchdog；不存在协作式降级。超时或未返回分支保留，超时正确结果也不计成功。

所有方法使用冻结 `verification.verify_any`，绑定原函数、结论种类、函数空间、容差，并对常数势核对独立解析值。错误原函数/空间、矛盾界、仅成功标志伪证均必须拒绝；探针异常或超时不能冒充正常拒绝。验证器仍共享受信任的底层数学代码，不是完全独立证明实现。

每题必须五次均预算内达标才算稳定成功，保留 `0/5` 到 `5/5` 的逐题结果、族/空间分项及全部失败。五次重复不算五个独立数学样本。模型身份、实际输入/输出/隐藏推理 token、费用和研发人工成本未知，不以字符、字节或工具 CPU 时间代替。

## 预先固定的三个成本门槛

1. **长期 80 轮资源门槛**仍对原四基线（旧默认、固定递增、验证选定固定、冻结 v317）。对于稳定成功数相同的适用基线，必须不丢失其稳定成功题，且完整冷 session 墙钟、CPU 中位数均至少减少 20%。前一增量修订不新增为每次必须再快 20% 的累计门槛。
2. **相对 `first_release` 的增量不退步**：没有稳定成功损失或可靠性退步，完整冷 session 墙钟与 CPU 的中位数以及五次合计均不得增加。这是 `≤1.0` 的原始数值门槛，不要求每次修订再提高 20%。
3. **旧六题冷成本回归门槛**：在单独 `run-regression` 阶段，相对冻结 v317 没有稳定成功损失，完整冷 session 墙钟和 CPU 的中位数以及五次合计均不得增加，保留全部五次原始数值。不能用在线提速抵消冷启动退步，也不通过四舍五入或事后容差带把失败改成通过。

精度、支持、可靠性、运行成本分别报告；没有综合分数掩盖退步。“更快失败”不构成收益。门槛在读取新种子前固定，不根据新留出表现调节。

## 运行顺序和放行门

解释器：`/PYTHON/bin/python3 -B`。入口：[release_evaluation.py](release_evaluation.py)。命令按顺序运行，计时不并行：

1. `self-test`、`initialize`：边界检查，公开验证题/已知任务账本，创建新种子的承诺。私有文件权限 `0600`，重复初始化不读种子。
2. `select-validation`：十五个冷进程选全局固定配置。成功数优先、有效证书数次之、配置较小再次之，不用运行时间选优。
3. `run-regression`：原六道公开题，六方法五次，先检查冷启动回归门槛。
4. `run-validation`：十三道公开验证题，六方法五次。`run-first-release-regression` 可另测上一公开十四题，它们不再算独立留出。
5. 主任务完成最终代码与正确性/启动失败测试后，再执行一次最终 `run-regression`，并写 `evaluation/acceptance_regression.json`：内容恰好为 `{"report_path":"evaluation/regression_<timestamp>/report.json","sha256":"该原始报告文件的SHA-256"}`。路径相对本目录 ROOT。随后执行 `freeze`，覆盖本目录所有 `.py`、本文件、公开协议/验证题/已知任务账本、验证选择、种子承诺、两个保留清单，以及这个最终回归指针和它指向的原始报告。两旧目录清单逐文件核对，任何旧种子的既有哈希只引用、不读取。
6. 主任务单独写内容恰好为 `{"action":"release_new_holdout","freeze_digest":"冻结清单的规范JSON摘要"}` 的授权 JSON；这是已有任务授权内的开发放行，不是另向用户索要许可。
7. `release-holdout --authorization <文件>` 才首次读取新种子、验证承诺、生成十四题并标注公开重合；不输出种子。
8. `run-holdout` 只使用已明确放行的实例，开始和结束核验冻结清单。完整结果及每个 session 原始返回保存在 `evaluation/`。

`write_freeze_manifest()` 返回所需 `manifest_digest`。读新种子前先核验清单与精确授权；禁止重冻已使用留出。按新留出修改实现会使该批题成为开发数据，必须另设未使用种子。新公开报告会另存带时间戳的目录，旧报告和失败记录不覆盖。

`checked_acceptance_regression()` 校验最终回归指针的两个字段、ROOT 相对路径、原始文件 SHA-256，以及报告属于当前版本/协议的 `regression` 阶段且 `old_six_cold_no_regression_vs_v317` 为真正的布尔 `true`。冻结前缺少该合格指针即拒绝；冻结清单同时记录指针内容及指针/原始报告文件哈希，后续每次检查都会重新核验，不允许在新留出揭示后换成另一次有利的回归报告。这里没有改变成本数值门槛；最终验收程序另从原始数据复算冷回归门槛。

首次[旧六题冷回归](evaluation/regression_20260919T234950969360Z/report.json)六方法均 `6/6` 稳定成功。runtime/v317 全冷墙钟中位数比 `0.976707`、CPU 中位数比 `0.977852`，五次合计比分别 `0.973438`、`0.975980`；严格不退步门槛通过。相对 first_release 的四项完整成本比也均小于 1。但 runtime 相对 first_release 在线墙钟约增加 15.3%，相对固定递增完整冷中位数仍约增加 12.2%，这些限制保留。

首次[十三题验证](evaluation/validation_20260919T235032762492Z/report.json)中 runtime、first_release、v317 均 `9/13` 稳定成功，三种简单基线均 `2/13`。runtime/v317 全冷墙钟和 CPU 中位数比分别 `0.749651`、`0.748824`，原基线 20% 资源门槛通过。但 first_release 的严格增量不退步门槛**未通过**：墙钟中位数比 `1.00024354`、五次 CPU 合计比 `1.00011940`，虽差异很小也不能事后放宽规则。墙钟五次合计比 `0.99995087`、CPU 中位数比 `0.99913148` 则略有减少。所有方法的错误证据误收、探针异常和 worker 失败均为零。

这些是允许继续改进的公开开发结果；不是新留出结果。后续运行须另存，不能覆盖这次严格门槛失败记录。

最终初始化失败恢复修复后，54项新测试和197项冻结回归通过；随后仅执行一次[最终六题冷回归](evaluation/regression_20260920T041824129864Z/report.json)，各方法仍6/6，runtime完整墙钟/CPU中位数为0.112625s/0.110469s，v317为0.115015s/0.112853s。相对v317和first_release的中位数及五次合计不退步门槛均通过。此报告由acceptance_regression.json绑定，作为冻结验收引用；此前失败和首次记录不覆盖。

“independent_new_instance”字段只表示相对known_public_tasks登记集合未重复的完整请求。该账本覆盖本协议13验证、旧6题、前修订14题，未声称穷尽全部历史开发曝光；同一函数、空间、目标量仅更换容差属于新的精度请求，不是独立新的数学问题。最终分析另按删除容差后的原题身份列出重合数，保留原抽样、不重抽，不改变费用或门槛。
