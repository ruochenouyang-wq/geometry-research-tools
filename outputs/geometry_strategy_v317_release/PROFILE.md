# v317 自动服务的公开开发剖析

本文件仅报告已经公开的 D05、D06、H04–H06，以及原题函数逼近和谱估计的 `1e-8` 检查。H04–H06 已经揭示，全部作为开发数据；这里没有新的留出结论，没有读取 private seed。冻结目录未作修改。

## 测量方法

解释器为同机 Python 3.12：`/PYTHON/bin/python3 -B`。每个任务分别启动 3 个新进程，每进程先运行一次，再复用同一服务运行 4 次；基于没有性能分析器的进程 CPU 时间取中位数。首次调用不预热，延迟导入、形状准备和初次缓存填充均留在首次在线时间中。模块导入、服务构造、标准库准备另行记录；外部最终证据重放也单列计费。子进程总墙钟包含启动和退出，进程结束前 CPU 另列。

每题另用新进程运行一次 `cProfile`，并用另一个新进程观察重复的完整谱证据重放。观察器仅记录完整证书及全部位置/关键字绑定的规范内容键，仍执行每一次原验证器；首次调用作为已计费预热，第二次才进行重复计数。未写入冻结模块，未实现或启用任何跳过验证的优化候选。`cProfile` 使用 CPU 计时，显著放大短函数开销，仅用于调用路径和相对定位，不用它的耗时声称提速。累计耗时有嵌套，不能相加。

适配器为 `ResearchService.evaluate_task`，不包含 `handle` 的证据存储和界面交互；不把这个实验推广为整套产品的端到端成本。运行机器未隔离，其他开发进程可能活跃，结果是描述性测量。

## 开销在哪里

五个松精度谱任务都只进行一次普通谱求解。每题 `fast_math.full_ground` 生成两个 sector，随后共有 `full_certificate` 3 次、`verify_sector` 6 次、`verify_full` 2 次：生成时聚合器先重放各 sector，控制器接收证书时重放一次，服务最后 `assess` 再重放一次。新进程 CPU 剖析中普通谱生成约占在线累计的 42–46%，而服务的最后一次 `assess` 约占 16.5–19.6%；生成本身包含聚合重放，不能把它们当作互斥开销相加。

同一组任务中 `diagnose` 仅占剖析时间约 0.16–0.21%。它读取已验证的精确上下界，做分数比较；删减这个诊断的收益很小，不应作为首要优化对象。

原题高精度谱的重复验证更突出。首次调用剖析显示 `verify_full` 27 次、`full_certificate` 31 次、`verify_sector` 62 次；`verify_full` 累计占剖析 CPU 约 68.1%。另一次不跳过任何验证的已暖观察中，`verify_full` 26 次只有 2 种完全相同的证书和绑定调用键，重复调用内原验证器 CPU 合计约 73.781 毫秒。这个数字是可消除重复计算的上界，不是已实现的节省：键构造、所有权隔离、命中检查和保护措施都有实际成本。

原题函数逼近走独立的自适应逼近路径。首次调用包含形状搜索；重复调用仍有证书构造及冻结检查，外部再重放约 26.2 毫秒。因此重复在线比首次快，不能把首次准备成本当作不存在。这里没有为了优化谱任务而改动逼近算法。

## 最小建议

优先实现一次服务调用范围内的完整证据重放复用。只有冻结验证器对同一完整不可变证书内容和同一原题、空间、精度绑定确实返回 `True` 后才可复用；上下文应包含验证器版本，严格限定生命周期和容量。输入不合法、绑定不同、证书任何内容改变都必须失效，并保留对外显式验证入口的真实重放。不能按可变对象身份、任务参数、求解器成功标志或仅上下界缓存。最有价值的是奇异谱路径反复使用的同一完整 source，其次是控制器与最后服务评估之间的重复检查。若要接入旧代码，宜构造隔离调用环境或显式依赖注入，不能让全局临时替换成为并发产品实现。

其次，重复请求应复用服务进程，并在发布计费中清楚呈现首次准备与累计摊销。当前导入约 44 毫秒、构造约 6 毫秒，明显大于松精度题的重复在线时间。复用是部署生命周期选择，不是数学算法提速；单次任务仍须计入真实初始化，不能拿已暖时间代表冷启动。无需为此修改候选参数、增项顺序或省略失败分支。

## 重跑

原始全部观测在 [metrics/profile.json](metrics/profile.json)，脚本为 [profile_release.py](profile_release.py)。基线命令：

```sh
/PYTHON/bin/python3 -B outputs/geometry_strategy_v317_release/profile_release.py
```

新服务提供相同的 `ResearchService(evidence_root=..., cache=False).evaluate_task` 接口后可传 `--services research_service release_service`。脚本会按轮次轮换服务顺序，分别计入两方的导入、构造、首次调用、重复调用、外部重放及分析成本，仍只使用这里的公开开发任务。重新运行会覆盖 `metrics/profile.json`；本说明中的固定表格是首次基线剖析，须在公布新数字时明确更新或保留其版本归属。
