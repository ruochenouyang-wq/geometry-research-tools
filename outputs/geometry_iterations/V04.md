# V4：把端点搜索与数学接受条件分开

V3 的每个端点都通过多轮有理惯性计算确定。本版用浮点带状消元先提出两个端点；浮点过程可以失误，最终端点仍必须通过 V3 的精确惯性和尾部正性条件。证书格式与数学作用域没有改变。

## 实质改动

1. 浮点寻找两个 Schur 包络的第 k 个过零点。
2. 加保护带，立即用有理数检查两个外侧端点。
3. 检查不通过就扩大保护带；仍失败则回退到完整有理二分。
4. 目标精度高于浮点能力时，在已验证的局部区间里继续有理二分。
5. 当两个内侧端点分别被精确拒绝，且两者的距离已超过目标宽度时，判定当前包络公式不可能靠继续二分达到目标，转而增加模式数。

第 5 步依赖两个包络矩阵随 x 严格递减。下界接受集合位于相应过零点左侧，上界接受集合位于相应过零点右侧。两个拒绝点给出当前两条包络根之间距离的下界。这是当前方法的限制，不是证明真实特征值本身存在不确定性。

所有最终结论由同一个 V3 复核器重算，浮点数组和搜索日志都不被当作证明。不会通过减小声明精度来冒充提速。

## 高精度能力与限制

局部有理二分允许本版在浮点候选定位之后，继续认证远小于浮点舍入尺度的区间。这解决的是特征值端点精度；还没有提高上一版试探特征函数的系数精度。后者另由 V7 研究。

支持 `1e-40` 至 1 的目标区间宽度，最多 64 个模式。若模式预算不足，返回有效但较宽的区间和 `target_not_met`。处理两个接近的特征值时，k 的正确编号仍由整个有限矩阵的惯性及尾部证明确定。

运行 `python3 -m unittest test_v04 -v`：6 项测试通过，包括故意提供错误浮点端点、空间不足、与完整精确搜索交叉核对，以及 `1e-30` 目标的有理细化。运行 `python3 bench_v04.py` 生成同模式数下的精度、计时和精确计数调用记录，保存在 `results/v04/`。
