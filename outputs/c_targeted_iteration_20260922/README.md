# C3：针对认证成本与错误细化方向的迭代

C3 是 C2 的独立后继版本。旧实现与最终数学验证器均保持原样。完整效果、失败和费用在 [总报告](REPORT.md) 中报告。后续发现的未达标题精度退步另在 [C3.1](../c_targeted_guard_20260922/README.md) 修正，本目录保留第一轮冻结实现。

## 改了什么

1. **复用精确搜索数据，延后完整核验。** 搜索已经算出的矩阵与候选统计用于生成待核验数据，避免组装时再完整重证谱间隔。只有数据序列化后通过原来的原题验证器，输出才会标记成功。没有用“已经验证”标签代替计算。
2. **强负幂势采用快速候选与有理后备。** 6、10 项空间先尝试 NumPy/LAPACK 数值库；按原函数重新计算精确残差。库不可用、分解失败、预算耗尽或误差不够小，都会留下原因并转回原有理候选路线。16 项仍用有理计算。较强谱界阶段先试 10 项，再试 16 项，不根据题号选路。
3. **平均零问题按实际区间选择分量。** 平均零指试函数在球面上的积分为零。对当前支持的正幅度奇异势，先构造各分量的完整上下界，再细化限制总精度的部分。保留平均零约束、全部角向分量和尾部的证明。没有把受约束问题替换为全函数空间问题。

弱负幂势保留 C1 的候选选择，只优化组装；阶跃势复用 C2；其它受支持路线沿用旧 C1 或基线。各次输出均注明实际来源、失败及回退原因。

## 使用

使用 Python 3.12；NumPy 为可选依赖。不安装 NumPy 也能走有理后备路径。需要保留相邻的旧 `outputs` 依赖目录，不能仅复制单个入口。

在项目根目录执行：

```sh
python3 -B outputs/c_targeted_iteration_20260922/controller.py
```

每行输入一个 JSON 对象，例如：

```json
{"kind":"spectrum","function":{"kind":"axis_profile","profile":"abs_power","axis":0,"amplitude":"2/3","exponent":"-2/7","offset":"0"},"mean_zero":true,"tolerance":"1/1000000","budget":{"wall_seconds":10}}
```

输出中 `certificate_valid` 表示原题证书有效，`target_met` 另要求达到原精度和预算；二者不能互换。内部组装器返回的 `verification_pending` 数据还没有经过最终核验，不能当作已证明答案。

程序内部以阶段检查管理预算，单次代数计算可能跨过检查点。需要严格时限时，应使用评估器的进程外终止机制；该期限包括导入、候选、验证及输出。NumPy 导入和失败后备成本都属于完整用时。

## 评测原则

固定 C2 与 C3 两个系统，保留原 24 道题，另外预先封存 6 道不同参数的题，开发者冻结代码前不查看它们。每题三次冷启动、交替顺序、同一原题验证器和 10 秒整体限制，共 180 次运行。28 道数学题与 2 道方法边界控制分开统计；正式性能期间只运行一个评测进程。

先前组件实验中约 97% 的认证耗时比例不能直接代表全部 C 流程，C3 是否改进必须由这次完整计时决定。评测不调用语言模型，未计量开发代理 token，也不把输出字节换算成 token。
