# 新发布版的预先公开评测

本协议用于修订版与四个参照的比较。原 v238–v317 的六道留出题已公开，现在只能作为回归。原目录全部冻结，旧私有随机种子不读取。新的随机种子只生成承诺；必须先完成验证选择、冻结所有新 Python 文件及保留清单，再由主任务明确放行，才生成具体新题。

## 比较对象与任务

所有方法接收相同原函数、精度、函数空间与总期限：

| 方法 | 固定策略 |
|---|---|
| `old_default` | 最早冻结数学工具的默认配置 |
| `fixed_increasing` | 原协议的 small、medium、large 顺序；遇到独立认证达标才停止 |
| `validation_selected_fixed` | 在下面全部验证题上，从同样三个配置选出一个全局固定配置 |
| `frozen_v317` | 原目录 `ResearchService.evaluate_task`，保持冻结实现 |
| `release` | 新目录 `release_service.ResearchService.evaluate_task` |

验证题在 [protocol.json](evaluation/protocol.json) 和 [validation_cases.json](evaluation/validation_cases.json) 完整公开：两道全空间/平均零精确常数、容易阶跃谱、阶跃函数逼近、三个负幂谱精度层级、全空间负幂谱、已知失败的负阶跃谱、固定 `-1/4` 的三个高精度函数逼近回归，以及其他负指数逼近支持边界。`-3/8` 的已知完整谱失败保留在内。共 13 题。先前固定 `-1/4` 的成果不得算作新的参数迁移。

未来新留出共 14 题：四道容易/精确题、六道负幂谱（`1e-6`、`1e-8`、`1e-10`，每个精度均含平均零与全空间）、三道其他负指数函数逼近（同样三个精度）、一道困难负阶跃谱。负指数、幅度与抽样规则预先写入协议。抽样不检查算法能否成功、能否支持或稳定界是否可用，不因失败换题。其他负指数逼近目前可能全部不支持，这仍是真实结果。这些题只检验已知数学族内的新参数，不能声称跨新数学结构泛化。

## 公平预算、重放与成本

容易题 3 秒，困难题 10 秒。每道题的求解、候选选择、完整证据序列化和独立原题重放合用同一个期限。固定递增的各分支不能各自领取完整期限。`SIGALRM` 必须在 Unix 主线程执行，超时异常继承 `BaseException`，不能被服务常见的 `except Exception` 吞掉；不提供协作式超时降级。另设父进程 watchdog 回收失控 session，失败题保留。超过期限的正确结果也不计达标。

独立评估器调用冻结 `verification.verify_any`，绑定原函数、结论种类、函数空间和精度，并对常数势检查独立解析特征值。证书格式未知、原题错误、只给成功标志均不能通过。验证器与求解器仍共享受信任的底层数学公式和代码，这不是形式化证明助手或完全独立实现。

每个方法每次重复使用新的 Python 进程，运行五次。重复间按预先固定方式轮换方法次序和题目次序。所有方法的数学模块导入与构造都位于初始化计时中；首次延迟导入落入对应首题费用。每个 session 内允许实现原有的缓存，跨 session 不共享。服务构造使用临时证据目录和 `cache=False`，避免将证据写入旧目录。

同时报告整进程墙钟/CPU、初始化、第一次任务延迟、在线求解及独立验证、错误证据探针、异常、完整序列化及 session 输出等。整进程费用包括解释器启动和所有导入，不能靠预先导入旧基线产生新服务提速。峰值 RSS 保留原始平台单位。验证选择的 15 个 session（3 配置 × 5 次）费用向选定固定基线计入一次，并保留其全部候选和失败成本；在线比较另列。研发模型 token、模型身份、输入/输出/隐藏推理、真实费用及人工研发成本均未知，不以字符数或工具执行时间代替。

每个 session 的每种可获得结论挑一个有效证书，执行原函数、空间、上下界、仅状态伪证四类攻击；函数逼近没有空间攻击。所有攻击必须拒绝，错误接受会阻止可靠性收益声明。异常和探针超时单列，不能称为正常拒绝。

## 预先声明的判定

五次都通过的题计为稳定达标，逐题同时公开 `0/5` 至 `5/5` 的结果。按容易/困难、数学族、原空间和函数逼近/谱分别列示，不能用容易题总数掩盖困难题失败。五次重复是运行波动，不是五个独立数学样本。

如对最强基线至少增加一道稳定留出成功、没有失去其成功题且无可靠性回退，可报告范围受限的族内精度收益。在稳定成功数相同、逐题没有成功损失时，只有整 session 墙钟和 CPU 中位数相对每个相同成功数的基线均减少至少 20%，才可报告初步整体运行成本收益。完整成本另含验证准备，不能用更快失败冒充提速。原始五次值、中位数、最小值、最大值和各基线得失题均保存；共享机器的小样本计时不宣称统计显著或跨模型能力胜出。各维度分别报告，没有用于掩盖退步的综合奖励分数。

## 可复跑入口与放行门

解释器：`/PYTHON/bin/python3`，加 `-B`。入口为 [release_evaluation.py](release_evaluation.py)。以下命令名作为该脚本的位置参数：

1. `initialize`：只写公开规则、验证题和新种子的 SHA-256 承诺。私有种子仅创建一次，权限 `0600`；初始化重复执行不再读取它。
2. `self-test`：验证伪证、错误原题/空间/结论、主线程硬超时、验证时间归属及旧种子读取禁令；不生成或读取新留出。
3. `select-validation`：五次独立冷启动比较三个固定配置。最大化总预算内成功数，再最大化有效证书数，再取声明次序较小配置；不以噪声计时选优。
4. `run-validation`、`run-regression`：五方法各运行五次；回归只读取旧已公开 `holdout_instances.json`。完整结果和逐 session 原始证据在 `evaluation/` 保存。
5. `freeze`：由主任务在实现完成后执行。清单覆盖新目录下全部 `.py`、本协议、公开规则、验证题、验证选择、种子承诺和 `PRESERVED_V317.json`。复核旧文件哈希，但旧种子的现有哈希只引用不重新读文件。不能重新冻结已经放行的留出。
6. 主任务单独写授权 JSON，且内容必须**恰好**为 `{"action":"release_new_holdout","freeze_digest":"冻结清单的规范JSON摘要"}`。此文件应放在 `evaluation/`。这是开发流程中的明确放行标记，不是额外要求用户批准。
7. `release-holdout --authorization <授权文件>`：验证清单和授权后，第一次读取新私有种子、核对承诺并生成题目；仅打印题数和摘要，不输出种子。
8. `run-holdout`：只使用已经放行的题目。开始与结束都检查冻结文件，保留五方法完整运行与比较。

`write_freeze_manifest()` 返回 `manifest_digest`；主任务可直接用于第 6 步。未冻结或未提供正确授权时，`holdout_cases()` 在读取新种子之前失败。实现改动若使用了本次留出结果，必须换新的协议与未使用的种子，不能在同一留出上修好后继续声称独立验收。

13 题的任务期限合计每 session 最多 102 秒，14 道留出最多 112 秒。通常实际用时较短；25 个完整 session 的纯任务预算上界分别约 42.5 与 46.7 分钟，初始化/探针/父进程 watchdog 另计。可以查看各运行目录的 `progress.json`，不要并行执行计时 session。
