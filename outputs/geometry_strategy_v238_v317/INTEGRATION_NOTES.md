# 组件完成后的接合与修复

这些工作用于把八组组件组成可运行系统，不另算成第 81 轮，也没有回写 80 轮的历史快照。最终文件可以与某一组件的末轮快照不同；最终冻结清单记录的是实际交付文件。

## 接合关系

`research_service.py` 接收请求，区分函数逼近和最低谱值估计，再选择对应路线。`verification.py` 按明确的证书格式选择检查方法，并把原函数、求解空间和目标精度绑定到结果。数学有效、精度达标、预算内完成分别记录。

自动逼近在选定分区后使用 `fast_math.piecewise_model` 构造同格式证书，再经旧验证器重放。显式谱计算和控制器的普通谱路线使用 `fast_math.full_ground`。新奇异谱路线使用 `adaptive_singular`，保留其原题完整覆盖检查。旧固定奇异族的同结果快速 `enrich` 另作为库接口保留，未声称新奇异路线已经复用了它的所有缓存。

## 实际发现及修复

1. 旧命令解析器拒绝新的 research、fetch、batch 及 view 字段。服务入口现先严格解析 JSON，拒绝重复键、非有限数和非对象，再由相应路由校验；真实子进程测试覆盖错误输入之后继续处理正常请求。
2. 常数势快捷路径原先绕过预算和策略校验。现先校验所有字段及数值，再执行精确常数谱公式。
3. 证书精度评估会覆盖控制器的超时状态。现保留数学精度结果，并独立计算完整服务调用是否超时，计入重放、摘要和存盘时间。该预算仍为同步的软预算，不中断正在运行的程序，也不包含进程启动及输出传输。
4. 新运输证书未必含内嵌容差；旧 verify 入口无法完整绑定它。通用验证入口现在根据实际证书类型检查，并用请求的容差评估目标，不凭求解器自己的成功标记验收。
5. fetch 原先绕过成本账目。现逐次记录请求、读取、重放、失败及时间。相同 verify 请求可以复用当前代码版本下的检查结果，缓存命中明确显示；fetch 每次重放。
6. 离线文本编码依赖存在 Python 二进制版本差异。修复和跨运行时检查另见 `INTERACTION_INTEGRATION.md`。
7. 公开开发题中，低精度奇异谱任务不必要地先构造奇异候选，占了新服务与简单递增策略约四分之三的时间差。集成策略现对允许宽度不小于 `1e-3`、且允许比较路线的任务先运行已有便宜直接谱探针；未达标仍保留奇异路线。没有降低探针的二分精度：开发对照显示那会导致本来一次可完成的题失去精度。阈值来自公开开发数据，最终留出仅用于之后的评价。

`test_service.py` 覆盖公开进程入口、常数捷径、错误目标绑定、缓存串题、批处理隔离、补读成本、完整调用预算以及函数逼近不能冒充谱结论。`test_integration_boundary.py` 另核对有效但未达标、端点篡改和结论类型。

## 计量修正与负结果

同结果性能探针的第一次尝试直接比较 `enrich` 的整个返回对象，因为其中含各次实际时间而停止。检查显示数学证书相同，差异字段为耗时与含耗时的尝试记录。修正后的 `benchmark_equivalent.py` 计入完整 enrich 调用成本，比较数学证书逐字段相同，使用旧验证器检查；不把耗时字段要求相等。

独立评测台未接入文本编码器，因此其 token 字段保持未测量。交互组件的离线编码实验单独报告，不把那组百分比套到整套算法或真实模型推理。

以上修复均发生在最终留出题揭示之前。后续报告同时保留开发比较、组件探针与最终留出结果；不把用于开发的题称作未见题。
