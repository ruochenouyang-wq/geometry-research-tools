# v278–287：依据证据选择下一步

本模块实现研究指导报告第 6–8、12–15 节中的一个小型、确定性的控制器。它只组织已认证的计算；不证明所选策略最优，不宣称已获得跨模型优势。

## 接口

```python
solve(request, solvers=None, verifier=None)
```

`request` 必须指定 `target` 为 `approximation` 或 `spectrum`，并给出原始 `function`。可选 `tolerance` 默认 `1/100000000`，`mean_zero` 默认 `True`。谱路线可指定 `route='auto'|'singular'|'spectrum'`。

预算 `budget` 支持 `max_attempts`（默认 8 次外层求解调用）、`work_units`（默认 2000000 个确定性调度单位）、`wall_seconds`（默认 60 秒）。调度单位不是时间、运算次数或 token。墙钟预算包含求解、失败、重放、诊断和调度，但在两次调用之间检查，不能中断正在运行的同步函数；迟到的正确证书会保留，同时返回 `budget_exceeded`。

策略 `policy` 支持 `compare_routes`（默认真）、`stagnation_patience`（默认 2）、`min_relative_gain`（默认 `1/1000`）。无收益停止只是预算决策，不是无法进一步改进的证明。

可注入 `solvers={'approximate': callable, 'singular': callable, 'spectrum': callable}`。每个函数接受一个动作字典，返回证书本身或含 `certificate` 的字典。可选 `singular_supports(request)->bool` 扩展奇异路线的适用范围；该能力声明只允许尝试，不能让证书通过验收。

独立验证回调签名：

```python
verify(cert, expected_function=None, expected_mean_zero=None,
       expected_tolerance=None) -> bool
```

谱证书必须通过回调对原函数、空间与目标精度的绑定检查；逼近证书按原函数绑定，完成标准另外比较 `error_upper`。默认验证器只接受冻结版本的数学证书。新的证书格式必须注入对应的可信验证器，不能通过返回 `verified=True` 自行获得信任。

结果包含 `certificate`、全部 `attempts`、`status`、`diagnosis`、`cost`、`route_comparison`、`rejected_actions`。`mathematical_target_met` 与 `within_budget` 分开记录；证书里较宽松的自报状态不能改变用户要求的误差目标。

## 诊断结论的强弱

在冻结的分区证书中，核心与环带的平方误差确实相加得到全域概率 L² 平方误差。根据较大项决定下一步，是启发式选择。

在已验证的分数幂证书中，令 `r=(H-μM)v`，投影残差平方为 `rᵀ M⁻¹r / (vᵀMv)`，空间外残差平方等于完整残差平方减去该值。这是精确正交分解；哪一种改进最便宜、能让最终谱区间改善多少仍未证明。`adaptive_singular_temple_v1` 的同形矩阵证书可使用该诊断，但必须先由注入验证器验收。

在直接矩证书中，可以精确找出全局下界是哪个分量界或角向尾界的最小值。径向分量内的表示、尾界不等式、端点二分误差尚未严格分开，输出明确标为 `hypothesis`。其他新格式缺少诊断时仍保留合法证书，不捏造误差来源。

## 本轮真实检查

最终 21 项测试包含真实旧求解器、真实矩阵/积分，以及针对失败路径的注入测试。新格式兼容性仅使用同形 fixture 检查控制流程；真实新后端由根任务集成后另验。

另运行四个开发算例，默认 8 次外层调用预算：

| 开发算例 | 请求目标 | 结果 |
|---|---|---|
| 固定 `-|z|^(-1/4)` 谱 | 区间宽度 ≤ `1e-8` | 4 次调用达标，约 `1.008×10^-10` |
| 同一势的 L² 逼近 | 误差 ≤ `1e-6` | 8 次后仍约 `0.001113`，如实保留未完成 |
| 负单位跳跃势谱 | 区间宽度 ≤ `1e-4` | 8 次后约 `0.0001040`，略未达标 |
| `-(1/2)|z|^(-1/3)` 谱 | 区间宽度 ≤ `1e-3` | 8 次直接矩调用达标，约 `0.0008934` |

这些是开发检查，不是留出集泛化结论或性能基准。路线比较会增加探测成本；重复调用默认旧后端仍重复部分计算。计时包含各阶段和失败，但缓存热度、硬件、并发负载未控制，不能据此声称加速。控制器自身不调用模型，注入后端的模型 token 未知时记为 `None`，没有把文本长度当作模型消耗。
