# C3G 定向回归评测

本轮在原 C3/C2 的 180 条结果公开后，针对 N29 的有效区间变宽问题建立。它不是新盲测，也不能代替原 30 题的完整性能比较。原代码、题单及结果不修改。

固定题为 E18、N29、N30、E13、E08、E19、E21、E24；所有原 case 对象和任务参数完整复制。依次覆盖正幅度平均零空间已达标、有效但未达标、无证书，以及负幅度平均零空间、阶跃、完整空间、逼近、方法不支持。共 7 道数学任务和 1 道边界控制，C3/C3G 各做 3 次冷启动，固定 48 条分母，串行轮换系统与题目顺序。

每条整个进程树的硬期限仍为 10 秒，包括导入、旧路线、守护后备、序列化、独立完整重放及写盘。父进程以进程组 SIGKILL 强制截止，不受求解器捕获异常影响。所有进度、尝试、错误、原始证书和输出保留；旧 baseline 后备失败、超时或没有改善的成本同样计入。

两个版本均通过原冻结 baseline.assess 按原任务完整重放，再以精确有理端点或逼近误差重新评分。只有原容差达标才算数学成功。不支持控制的明确拒绝单列，不能算求解成功。

N29 另有外部质量标准：其有效区间宽度应恢复到不大于原轮 C2 三次一致的精确宽度。该有理数及原报告哈希预先写入 protocol.json，仅用于父评估汇总，从不传入求解器，也不改变原 1e-6 容差。每条同时报告恢复标准和原容差是否通过；有效但仍过宽的区间依然判数学失败。所有题均报告有效区间退步、有效证书丢失和原目标成功丢失。

CPU 使用外层 wait4 已包括被工作进程回收的子进程，不再次加总；RSS 是观测到的最大单进程高水位，macOS 单位 bytes，不冒充同时进程树总内存。硬中断时未回收后代成本可能低估，并有逐条标记。记录原响应及证书的规范 UTF-8 JSON bytes，它们不是 tokens。模型 API 调用为 0，模型与缓存 token 数未知。

冻结引用原 C3 的 636 文件完整依赖集合和源码归档，并加入本目录实现 Python、protocol.json、cases.json。newguard.py 若在冻结前存在也纳入；冻结后新增、改动或删去任何实现都会使正式结果无效。evaluation、notes、review、results 下输出不进入源码集合。环境及明确单线程控制在冻结与运行前后核对，不额外预热冷工作进程。

入口：以同一 bundled Python 执行 `selftest_evaluate.py`（仅合成测试），再执行 `evaluate.py freeze` 和 `evaluate.py run`。必须实现和独立审查通过后冻结；本轮根已授权冻结完成后串行独占运行。报告保留所有 48 行，只有双方 3/3 成功的同题子集比较成本。三次重复仅给描述性统计，不据此宣称显著性或跨任务总体优势。
