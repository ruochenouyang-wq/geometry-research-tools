## 为什么当前复用没有替代数学检查

私有 `direct`、`fast_math`、`adaptive_singular`、`verification` 与 `research_service` 模块分别执行相应冻结源文件。替换的是这些私有实例的依赖引用；共享旧模块的 `verify_full`、`verify_sector`、`full_ground`、`certify_sector`、`Kernel`、注册验证器、旧服务验证入口和 `importlib.import_module` 的对象身份在审查前后保持相同。私有模块名也没有注册到共享 `sys.modules` 中。

完整证书、绑定、验证器类别和版本都进入规范内容键。只有精确的 JSON 原生类型可缓存，`True` 与 `1` 的内容键不同；缓存只保存验证器实际返回字面值 `True` 的结果。首次缺失时验证器得到独立的完整内容快照，外部证书对象及绑定对象不会被检查过程改写。任意数学内容改变后重新检查；原题、平均值空间、精度、sector 的 `expected_m` 和递归深度改变后也重新检查或明确拒绝。

sector 层复用没有把生成器成功标志当作证据。独立测试观察到首次 sector 重放确实构造冻结 `direct.Kernel`，相同完整内容再次调用才复用；这个 Kernel 与加速生成器的 Kernel 是不同实现，冻结构造函数的代码也相同。验证过的 sector 可以用于再次重建完整聚合证书，但篡改全局上下界、遗漏部分下界或者重排 sector 仍被拒绝。父证书被拒绝时，未修改且已经验证的子 sector 发生缓存命中是正常情况，不能把命中总数直接解读为“坏父证书被接受”。

两道公开参数的普通谱生成与冻结生成结果逐字相同，原题高精度任务关闭和开启复用时完整证书逐字相同；结果还通过未接入缓存的旧验证器进行原题、空间和精度绑定检查。

## 本次确实发现并修复的问题

1. **非 JSON 类型被悄悄转换。** 早期版本将 `sectors` 从列表改成元组后，旧验证器返回 `False`，新缓存却在缺失和命中时都返回 `True`，因为 JSON 往返把元组转换回列表。当前版本在规范化前严格检查类型，非 JSON 值使用保留原类型的独立副本重放；两个独立回归检查均通过。
2. **过深嵌套的失败形态改变。** 严格类型检查加入后，约 1200 层额外嵌套会在回退的 `deepcopy` 阶段抛出 `RecursionError`，旧注册验证器则返回 `False`。当前只在快照阶段捕获该错误并拒绝，开启和关闭复用的回归检查都通过；检查器自身的其他异常仍按原有方式传播，且没有成功结果残留。
3. **复制上下文可以延长会话对象的寿命。** `copy_context()` 会继承同一个可变会话对象，简单地重置父 `ContextVar` 不会清除复制上下文中的对象。当前父会话退出后标记关闭并清空内容，旧上下文不能再次命中，重新进入请求会创建新会话。另一个测试在复制上下文的检查已经开始后关闭父会话，再让检查完成，确认已关闭会话不会重新填充缓存。

初版测试还随 sector 缓存扩展而更新了计数断言：只要求被拒绝的父证书没有成功缓存记录，允许它的未修改子 sector 命中。这是测试适应真实层级结构，未放松证书拒绝条件。奇异证书实际使用 `matrix_digest`，相应攻击检查针对该字段，而非不存在的矩阵展开字段。

## 检查覆盖

- 普通谱：上下界、宽度、角向尾部、遗漏 sector 起点、无限空间声明、惯性、径向尾部、模式数、sector 原函数、sector 序列和布尔字段篡改。
- 奇异谱：完整 source 及其 sector、source 摘要、残差、Rayleigh 值、质量、系数、矩阵摘要及完整残差声明篡改。
- 原题绑定：函数参数、轴、精度、结论类型、`mean_zero`、`expected_m` 及布尔/整数/浮点/字符串混淆。
- 所有权与生命周期：调用后修改原证书、非 JSON 回退、非有限数、循环结构、过深结构、非字面 `True` 的返回值、异常恢复、容量耗尽、嵌套会话、独立服务实例、复制上下文、关闭中的并发检查。
- 并发：同一运行时的四个独立线程拥有不同会话；同一服务的两个线程同时处理不同公开原题，结果均保留正确绑定并经旧验证器重放。

## 使用边界

当前服务是同步接口，不产生后台任务。正在执行的同一请求内部复制上下文时，共享该请求的会话是设计行为；请求结束后关闭会话是实际边界。上述有限并发检查不代表对任意异步宿主、进程内恶意代码或所有调度交错的全面认证。

缓存信任固定的冻结检查器及宿主代码。它不能防御同一进程中有权限直接替换检查器或修改缓存字典的恶意 Python 代码，也不是新的数学证明系统。容量统计只约束规范键的字节数，不是完整 Python 内存峰值。嵌套检查的诊断计时存在重叠，不能相加声称总耗时或节省；应使用完整服务调用与外部验收的实测总时间。
