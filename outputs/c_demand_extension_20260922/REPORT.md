# 沿 C 思路的扩展：C2 新题测试与回退分析

日期：2026-09-22。旧 C 在本文记为 **C1**，新扩展记为 **C2**，**基线**指开发 C1 之前的原算法。

**主要结论：C2 把稳定达标题数从 20/22 提高到 21/22，新增解决旧失败题 E19；但双方共同成功题的总耗时增加 5.65%。** 本轮没有新增掉分题，也不能称为全面提速。20 道新公开题的达标数仍是 19/20，覆盖率增益来自明确列出的旧失败回归。

## 1. 这次解决的任务是什么

测试对象仍是单位球面 S²，即满足 x₁²+x₂²+x₃²=1 的曲面。我们给球面指定一个势函数 q，并寻找某个能量表达式的最小值。这个最小值叫作**最低谱值**；程序给出的上下界必须包含真实值，两界之差必须不超过用户要求的误差。

测试包括负幂势 q=b+a|z|^α 和阶跃势。这里 z 表示选定轴方向的坐标，a 控制幅度，b 表示整体偏移；负指数 α 会让函数在 z=0 附近变大，这种局部无界行为称为**奇异性**。阶跃势在球面的两个半球取不同常数。**完整空间**允许所有满足必要光滑性和有限能量要求的试函数；**平均零空间**另外要求试函数在整个球面的平均值为零。

另外两题要求逼近函数本身，使用 L² 误差，即对整个球面的误差平方求平均后再开平方。这与最低谱值区间宽度是两种不同目标，不能混算精度。

本轮的“其它题”是新函数参数、更严格精度、不同函数类型、空间约束和符号的组合。轴方向变化仅检验旋转一致性，不代表已经推广到新的几何维数。这里没有宣称解决数学界的公开未解问题。

## 2. 延续 C 的核心：从所需结论决定计算量

**试函数**是用来近似最优解的候选函数。把它代入能量表达式得到的值记作 μ，叫作 **Rayleigh 值**。试函数代入相应特征方程后剩下的误差叫作**残差**；其完整平方范数记作 v。这里的“完整”意味着不能只检查有限个坐标而忽略剩余方向。

如果已经证明相关分量的第二个谱值不小于 β，且 μ<β，则可以利用 **Temple 不等式**——一种把残差转成谱值误差界的不等式——得到该分量最低谱值的区间：

λ₁ ∈ [μ − v/(β−μ), μ]。

因此，要得到误差不超过 ε 的结果，可以直接检查 v/(β−μ)≤ε。程序不必把每个中间量都计算到同样高的精度，而应选择对最终不等式有用的计算。最后仍须完成其他分量和无限维余项的认证，才能得到原题的全局结论。

C2 延展了两个方向：

1. **阶跃函数逐级提高次数。** 原算法固定使用十次多项式。C2 从较低次数开始，按 2、4、6、8、10 逐级尝试，用精确的全局区间宽度决定停止。达到要求后不再继续提高次数。要求很严格时，前面的尝试可能成为额外成本。
2. **强奇异函数先改善可用谱界。** C2 先取得真实可验证的粗 β，以及最低谱值的粗下界。后者指导迭代的移位，帮助更快找到较好的试函数。如果首个低阶候选仍满足 μ≥β，就先扩大用于证明谱界的比较系统，而不是在同一个松谱界下连续提高试函数复杂度。这是搜索顺序的启发式，不是“其它候选不可能成功”的证明。

**证书**是包含确切有理数、必要界限和验证信息的数据。C2 继续产生原格式证书，交给原验证器按照原题的函数、空间和容差重新检查。数学验收条件没有放宽。近似候选、较宽但有效的区间、不支持和超时，都不能算作达标。

## 3. 如何比较

固定题单共有 24 题：20 道新公开开发题、2 道旧题结构回归、2 道预期超出现有方法范围的控制题。主要数学成功率的分母是 22；边界控制另外报告。新题中包括 18 道谱问题和 2 道函数逼近问题。

E19 与上一轮失败题 S09 的数学任务完全相同。E20 使用旧 S06 的函数与空间，但把精度从 10⁻⁶ 提高到 10⁻⁸，因此属于更严格的回归扩展，并不是原题原样复测。

三个系统分别运行三次，每次从新的 Python 进程开始。共 216 条记录，始终串行，轮换系统顺序。**稳定成功**表示同一题三次全部通过。每次十秒的外部硬期限覆盖启动、加载、求解、输出以及评测器对证书的独立完整重放。

源码和题单在正式运行前固定；此前的功能测试、失败诊断及其修复单独保存，不能混入本轮提速比较。本轮是公开开发测试，不是开发者完全未见过的独立保留测试。

速度只在双方都稳定成功的相同题目上比较。墙钟时间是用户等待的实际时间；CPU 时间是处理器执行工作的时间。候选子进程的 CPU 已计入，不能再次重复相加。内存指标是观测到的最大单进程峰值，不是所有同时运行进程占用内存之和；强制终止期间未回收子进程的资源计量可能不完整，原始记录有相应标注。

## 4. 开发中确实出现过的问题

这些记录发生在正式冻结之前，均保留原始文件，没有作为最终算法的成功成绩。

- **强题从功能成功退回到超时。** E19 曾在组件功能检查中成功，但统一入口联调出现了三次预算失败。前两次可能与其它开发测试重叠，不能据此量化环境干扰；第三次记录明确显示，末轮候选仅获约 1.37 秒，而组件仍有约 2.73 秒可用，预算被重复预留。
- **在过松谱界下重复优化候选。** 初版在 12 模比较系统的 β 很低时，仍依次尝试 6、10、14、16 项候选。轨迹显示这些候选没有进入可用间隔，之后才扩大到 16 模。最终版改为首轮失败后优先改善谱界；它保留所跳过的步骤和调度理由，不把这个选择包装成不可能性证明。
- **最后一轮提前被终止。** 根入口已预留约三成时间用于验证或回退，末轮子进程又只得到剩余组件时间的一半。最终版只在最后一个候选上改为保留 0.15 秒，仍保留单候选两秒上限和总十秒硬期限。
- **预算中断可能丢失已有较好候选。** 独立审查发现，两条扩展路线可能在后续步骤耗尽预算后丢掉此前的较好候选。已改为保留或重建完整证书；重建失败时仍返回完整候选资料，并明确标为“未经验证”，不计成功。

这些修正覆盖了调度和证据保留问题；它们没有证明算法已经对任意机器负载稳定，也没有把运行超时解释为数学问题无解。

## 5. 固定评测结果

216 条运行全部完成，冻结前后 619 个文件的身份一致，其中 604 个来自既有项目。以下通过数均要求三次全部成功。

| 测试范围 | 基线 | C1 | C2 |
|---|---:|---:|---:|
| 20 道新公开题 | 19/20 | 19/20 | 19/20 |
| 2 道旧结构回归 | 1/2 | 1/2 | **2/2** |
| 主要数学任务合计 | 20/22（90.9%） | 20/22（90.9%） | **21/22（95.5%）** |
| 2 道方法边界控制 | 均未求解 | 均未求解 | 均明确拒绝，不计成功 |

### 5.1 新能力：E19 稳定通过

E19 要求完整空间中势函数 q=−3|z|^(−2/5) 的最低谱值区间宽度不超过 10⁻⁸。基线和 C1 三次都未取得达标证书；C2 三次全部成功，完整时间分别为 **6.703、6.515、6.681 秒**，中位数约 **6.68 秒**。

实际证书宽度为约 **1.36247×10⁻⁹**，最低谱值约为 −5.664355393。精确端点保存在有理数证书中。这里的收益是由失败变为成功，不能把旧算法较短的失败耗时拿来计算“加速倍数”。

### 5.2 速度与消耗：有代价的能力扩展

下表只计三者均稳定成功的同一组 20 题，共 60 次运行；E19 和其它失败、边界控制不混入速度比。

| 指标 | 基线 | C1 | C2 |
|---|---:|---:|---:|
| 完整墙钟时间合计 | 90.172 秒 | **69.194 秒** | 73.106 秒 |
| CPU 时间合计 | 89.010 秒 | **68.258 秒** | 71.967 秒 |
| 单进程峰值内存的中位数 | 34.63 MiB | 34.71 MiB | 34.73 MiB |
| 证书数据总量 | 1,807,890 字节 | 1,799,355 字节 | **1,721,307 字节** |
| 完整响应数据总量 | 2,227,185 字节 | **2,177,076 字节** | 2,352,034 字节 |

MiB 是内存单位，1 MiB=1,048,576 字节。内存行不表示进程树同时占用的总内存。C2 候选阶段同时存在父子进程，因此单进程峰值接近不代表总内存相同。响应体积不包含所有独立日志文件。

C2 相对基线节省墙钟时间 **18.93%**、CPU 时间 **19.15%**；相对 C1 则分别增加 **5.65%** 和 **5.43%**。C2 证书总量比 C1 小 **4.34%**，但完整响应增加 **8.04%**，原因包括更详细的尝试和候选保留。因此，不能声称本轮已经降低模型 token 消耗。

分组更能说明取舍：八道阶跃题的 24 次总耗时，C1 为 10.381 秒，C2 为 10.017 秒，减少约 **3.50%**；共同成功的四道强奇异完整空间题 E14/E16/E17/E20，C2 总耗时却增加约 **11.59%**。新路线增加了谱界证明、候选进程启动及检查成本。这些步骤帮助解出 E19，但对本来就能解出的题不一定划算。本轮没有逐项关闭组件的对照实验，不能把这 11.59% 精确分摊给某一步。

逐级搜索也不保证节省时间。例如 E03 从固定十次改为依次尝试二、四、六、八次，最后在八次达标；尽管最终次数较低，中位时间仍从 0.386 秒增至 0.425 秒，增加约 **10.0%**。原因是前几级尝试也需要付费。E01 则从 0.420 秒降至 0.373 秒。只有三次重复，小幅差异应视为初步结果。

还需区分“满足同一精度要求”和“实际得到完全相同精度”。例如 E01 的目标为 10⁻⁶，C1 实际达到约 1.04×10⁻¹⁴，C2 达到约 3.58×10⁻⁹；两者均达标，C2 减少了多余精度。逐题实际误差已保存在表格中。

### 5.3 未达标、回退与不支持，逐项说明

**E18：有效证书仍不够精确，且主导分量判断暴露弱点。** 本题是正幅度势 q=(2/3)|z|^(−2/7)，要求平均零空间、误差 10⁻⁶。三种算法均返回有效区间，但宽度约 **3.86244×10⁻⁶**，约为允许值的 3.86 倍；这不是伪证书或超时，而是精度未达标。

把试函数按照绕指定轴的角向变化频率分成不同部分，叫作**角向模态分解**；整数 m 标记相应频率。原 C 重点细化 m=1 分量，但本题证书已经证明 **m=0 分量决定最低值**：m=1 的下界仍比 m=0 的上界高约 0.287874。整体区间的两个端点都来自 m=0 的原有区间。因此，继续优化 m=1 不能收窄真正卡住的区间。回退轨迹提供了更直接的证据：m=1 的残差平方从约 5.69×10⁻³ 降到 7.45×10⁻¹⁹，而四轮计算的全局宽度始终是完全相同的有理数。

轨迹中三次出现“试图排除其它分量的下界高于其已证上界”，正是这个冲突的具体证据。C2 结束 C1 候选序列后回退基线，基线仍返回相同的宽区间。下一步应让控制器识别需要细化的分量，并给 m=0 构造更好的试函数或上下界；不应只增加 m=1 的次数。该结论针对本题，不等于已经证明某条连续参数曲线发生了谱值交叉。

**E21、E22：有意使用原有函数逼近路线。** C2 本轮新增的是谱问题搜索策略，这两题直接沿用基线，三次均达标。它们是成功的基线路由，不应列为 C2 新算法的独立能力。

**E23：到达强残差方法的适用边界。** 指数为 −1/2 时，当前试函数体系所需的平方势矩在奇点处不再可积。C2 明确拒绝使用这套方法，不表示原算子不存在或问题不可求解。

**E24：完整空间正幅度负幂势尚未接入本路线。** C2 明确报告不支持。这个限制是实现和证书路线的支持范围，不是数学不可能性。

**内部尝试失败仍有保留。** 比较阈值超出当前可证明的余项界，或候选尚不满足 μ<β，都会在轨迹中留下失败原因。这些是正常搜索拒绝；最终是否成功只看完整证书。正式冻结后的 C2 共 72 次运行：63 次达标、3 次精度不足、6 次明确不支持，没有执行异常或总硬期限超时。

按成功题的实际来源分，C2 有 **13 题使用新增路线、6 题复用 C1、2 题沿用基线**。不支持控制不算新增路线的成功成果。

## 6. 证据与适用边界

功能与控制流检查包括阶跃路线 11 项、完整空间初版 11 项、最终调度 4 项纯模拟回归、统一入口 9 项，以及评测器 62 项合成检查。最后的数学性能结论只依据冻结后的完整比较；早期功能检查不是最终性能成绩。

独立审查见 `notes/MATH_REVIEW.md` 与 `notes/EVALUATOR_REVIEW.md`。它们检查了证书验收链、预算和资源计量，但这仍是基于现有数学实现的程序验证，没有使用形式化证明助手从公理开始检查全部分析论证。

数值评测程序没有调用模型 API；开发过程中各代理的 token 也未单独计量，因此这里没有实测的模型 token 对照。证书字节数衡量输出数据量，不能换算成已节省的 token。这轮结果也不能直接证明“较小模型半小时超过较大模型八小时”；要检验这个目标，仍需固定模型、提示、题目和预算的端到端对照。

## 7. 下一轮最值得做的工具

优先级最高的是**主导分量识别与按需细化**：先比较各个已认证区间，把计算投入到决定全局下界的分量。这直接对应 E18 的已证败因，比继续统一增加试函数次数更有针对性。

其次是**按成本选择路线**：保留 C1 已经较快的路径，把新增强谱界方法用于旧路径缺乏进展的情况。触发条件应来自剩余误差、证明余量和已经消耗的工作，不能写成“遇到 E19 就用新算法”的题目查表。

第三是改进逐级次数选择，减少 E03 这样的前级重复计算；同时把完整可恢复证据与简短模型回执分开保存，再用实际模型调用测量 token。本轮只完成原因分析和建议，没有在看过正式结果后继续改代码以美化同一轮成绩。
