## 1. 谱界与候选路线

### 完整第二特征值下界与径向尾界分离

`fullspace_extension._gap_at` 要求比较阈值严格小于 `kernel.beta`，然后调用冻结 `spectral_gap._certificate`。这里 `kernel.beta` 是未显式保留径向部分的下界，**本身不是**第 2 特征值下界。

设完整径向块在阈值 (x) 的 Schur 补为 (S(x))，冻结完整尾部构造给出有限矩阵 (L(x)\preceq S(x))。当尾部严格正且 (n_-(L(x))\leq1) 时，完整算子在 (x) 以下至多有一个谱值，因而 (\lambda_2\geq x)。零惯性不计入严格负方向；允许 (x=\lambda_2)。粗搜索每个接受端点仍由该证书重建，且 `verify_gap` 绑定同一势、`m=0`、`mean_zero=False`、第 2 个径向谱值以及完整尾部参数。未见用尾界替代谱隙的错误。

### 平移与精确残差

候选子进程先重放同题的 `verify_ground`，取 `shift = ground.lower - 1/1024`。因此 shift 严格低于该径向块的最低谱值，有限试验空间上的 (H-\mathrm{shift}M) 正定；该平移用于提出候选，不改变原算子的目标值。

候选评价使用原势的完整强作用矩阵 (R_{ij}=\langle H\phi_i,H\phi_j\rangle)，而非有限 Ritz 矩阵的残差。冻结 `fullspace_singular.trial_matrices` 从幂函数作用重新积分，并核对弱作用与强作用一致。对归一化商 (\mu\) 及完整残差平方 (v)，只有 (\mu<\beta\leq\lambda_2) 才使用

\[
\mu-\frac{v}{\beta-\mu}\leq\lambda_1\leq\mu.
\]

`full.certificate` 重建这些量，控制器随后对序列化证书调用冻结任务绑定验证器。工作子进程的统计摘要只能指导搜索；仅修改其宣称的宽度或残差不能通过最后重建。

全空间路线只接收 `mean_zero=False`。轴对称势的全空间最低谱值等于 (m=0) 径向最低谱值：对 (m\ne0) 的径向函数去掉角向因子，其 (m=0) 二次型少掉非负项 (m^2/(1-z^2))。该论证不可以直接用于均值零问题；当前代码没有这样使用。C1 均值零路线继续使用自身完整扇区证书。

### 阶跃势全局组合

新 `_screen` 的标量组合与冻结 `step.trial_certificate` 一致。选定块的 Temple 下界与该块已有下界取最大，再与其他所有显式扇区及未枚举角向尾下界取最小，最后与全局逐点势下界（均值零时含球面 Poincaré 常数 2）取最大。上界取该候选 Rayleigh 商与完整来源上界之最小。没有以一个块的改进冒充整个球面的改进。

默认阶跃谱隙 `(m+1)(m+2)+min(q)` 是该单一实径向块的第 2 个自由谱值加势下界：全空间候选 (m=0)，均值零候选 (m=1)。它不是整个球面按重数排列的第 2 个谱值。源码的使用范围正确。

`selected_sector_lower >= beta` 只证明固定 beta 无法为该块任何试验函数提供严格 Temple 条件，不证明原题无解。其他扇区限制的诊断也明确只针对当前候选。

上述 min–max、负子空间计数及 Temple 关系与既有数学审查采用的 [Teschl 原始教材，第 4 章](https://www.mat.univie.ac.at/~gerald/ftp/book-schroe/schroe.pdf) 一致。本次逐式核对新代码，并未扩展成文献综述。

## 2. 绑定、缓存与验收

- `runtime.verify` 将外部原题正规化后交给冻结 `baseline.assess`。势函数（包括 axis、参数）、目标精度和均值零约束须同时匹配；候选目标达标声明不替代重放。
- 原生 C2 证书先经历 JSON 往返再重放。有效但过宽的证书保持为 open；负宽度或相互矛盾的端点不能被当作成功。外层评测再次根据 `upper-lower` 和原题精度计算宽度，并要求独立重放结果 `certificate_valid is True`。
- baseline 回退只缩减可用时间，没有缩减原数学目标精度或改变原题。控制器复用冻结 baseline 自己的返回判定；外部评测仍再次重放回退证书。这里的信任对象是冻结、已绑定任务的实现，不是任意求解器状态字符串。
- 未见新代码替换旧模块中的 `normalize`、矩阵构造或验证函数。旧阶跃矩阵缓存返回三层 tuple，新路线只读取；全空间矩阵在构造时重算。C1 的工作对象和计数包装不修改共享 Kernel 类。
- 同一 Python 进程内通用模块名仍可复用既有模块和缓存；这不是任意宿主环境的模块隔离保证。当前评测每系统、每题、每次重试均启动新进程，且检查 C2 runtime 来源，因此不会由在一个常驻进程中先跑 C1 再跑 C2 造成跨系统热缓存优惠。冻结文件与运行来源的最终哈希一致性由评测冻结审计负责。
