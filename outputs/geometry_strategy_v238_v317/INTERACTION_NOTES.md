# v308–317：交互、证据与总成本

本组件不调用语言模型或网络。所有模型费用与实际 API 用量均为 `null`；文本编码数量不映射到 5.6、Astra 或隐藏推理用量。30 项测试包含冻结分段证书和新运输证书的实际重放；其余带模拟验证器的例子只检查交互与计数行为。

## 调用约定

- `summarize_result(result, request=None, verifier=None, places=12, ledger=None)`：保留目标、函数、空间、量的类别、精确界、向外舍入的小数界和证据状态。状态由精确宽度或误差上界重算，不相信证书自报状态。没有目标只报 `certified_bound`；没有验证器只报 `unchecked`。
- `verifier(certificate)` 必须返回字面布尔值 `True` 才能标为已验证。调用方应把验证器闭包绑定到原函数、空间及相应目标；本层不另写一份数学规范化器。合法的 `certified_open` 结果仍需能通过证据有效性核验，不能把未达目标误当成证书无效。
- `present_result(..., store=callback, include_certificate=False)`：`store(sha256, certificate)` 返回可取回的字符串位置。默认返回引用；没有存储回调时保留完整证书，避免无声丢失证据。存储是否持久由回调负责。
- `retrieve_evidence(reference, load, verifier=None, require_verified=False, ledger=None)`：`load(locator)` 返回证书对象；先核对 SHA-256 和记录的字节数，再可选地重放数学证据。哈希一致本身只证明内容身份。
- `RequestRunner(executor, namespace, cache=True, ledger=None, max_cache_entries=128, max_cache_bytes=16777216)`：执行器接收独立请求副本、返回对象。`execute` 返回结果与资源信封，`batch` 保持顺序并独立处理错误。命名空间应反映执行程序和数学版本。
- 去重只针对完全相同的已给请求；不把省略字段与显式默认值自行合并。调用方若有已审查的语义规范化器，可在此层之前使用它。求解空间、原函数、目标、预算字段都会参与缓存键。
- 缓存适用于确定性任务。需要重新随机搜索时关闭缓存。LRU 优先保留最近使用的结果；容量上限约束序列化证据字节，不声称约束整个 Python 进程内存。
- `UsageLedger(max_requests=None, max_executions=None, max_wall_seconds=None, clock=None)`：失败返回与异常均计入；开始过的执行会消耗执行预算。缓存命中消耗请求预算但不消耗新的执行次数。墙钟预算只在接纳下一请求时检查，不会中断已经运行的调用。
- `ledger.stage(name)` 可包住额外步骤。已有请求键、执行、缓存读写、验证、存储和取回分别计时。嵌套阶段会重叠，不能把各阶段之和当作总墙钟；总墙钟还包括空闲等待。

## 保留意义的压缩

`reasonable_summary` 是实际比较基线：去掉完整请求的重复副本，并去掉与证据引用重复的同一摘要值；仍显式包含原函数、范围、目标和精确界。

`bind_summary` 仅去掉可由当前可见原请求恢复的重复函数、空间开关或目标，并以请求编号和完整请求哈希绑定。同时，若存储位置中含有同一证据哈希，则保存其前后两段，避免传两遍哈希。`expand_bound_summary` 恢复原摘要，并拒绝错误请求编号、修改后的请求和不合法恢复标记。它恢复语义，不替代数学验证。

`choose_response` 在两种编码下都不变长时才选择绑定回执；否则返回合理精简基线。首次说明协议的文本被包含并计数；`protocol_known=True` 只能在说明已经存在于可见上下文时使用。传给用户的是返回值的 `response`，比较统计是本地计量数据；若调用方也传这些统计，必须计入额外文本。

## 可见文本的实际对照

使用旧 `token_meter.py` 的编码加载器及 `tiktoken==0.11.0`。公开编码缓存只读复制到本轮 `token_cache`，加载前按已知 SHA-256 核验；缺缓存、编码依赖或版本不符就报不可测，不下载，不用字符数冒充 token。词表来源与许可沿用冻结版本的 `token_cache/SOURCES.json` 和第三方通知。

`measure_conversation` 计入完整说明、输入格式、每个请求、每次返回及补读证据。测试用三个已保存证书组织预先规定的交互场景，不是模型产生的行为；完整文本在 `iterations/v317/CONVERSATION_TEXT.json`，计数在同目录 `TOKEN_COMPARISON.json`。

| 场景 | 合理精简基线 o200k / cl100k | 新策略 o200k / cl100k | 节省 |
|---|---:|---:|---:|
| 单次、未预先说明协议 | 308 / 305 | 308 / 305 | 0 / 0 |
| 12 次、不补读 | 5922 / 5878 | 5753 / 5674 | 169 / 204 |
| 12 次、补读 3 次证据 | 21064 / 20825 | 20895 / 20621 | 169 / 204 |
| 12 次、每次补读证据 | 66490 / 65666 | 66321 / 65462 | 169 / 204 |

12 次场景计入了一次额外协议说明。不补读场景约节省 2.85% / 3.47%；大量补读后占比下降。单次情况下，协议成本超过收益，策略因此保持原基线。只把原题改成哈希而不消除引用内部的重复，会出现负收益，消融数据同样保存。没有将完整大证书作为唯一弱基线，也没有删除精确分数来制造优势。

## 十轮的实际改变

v308 保存目标与证据状态；v309 精确状态和向外舍入；v310 证据存储引用；v311 按需取回检查；v312 完整请求绑定去重；v313 批量错误隔离及合法运输证书兼容；v314 失败也消耗预算；v315 累计阶段计时；v316 有界缓存和冷暖条件；v317 完整会话计数、可恢复压缩和拒绝负收益策略。每轮在代码变化和通过相应测试之后记录，`iterations/v308` 至 `v317` 保存当时源码与对照。

本轮主要结果是可靠交互和可复核计数。真实运行时间可能受并行开发影响，确定性时钟测试只证明计时账目正确，不用它宣称运算提速。没有做真实模型理解率、实际推理 token、API 费用或跨模型能力测试。
