# v238–v317 与后续发布修订：需求和证据审计

审计日期：2026 年 9 月 19 日。审计对象是已经冻结的 v238–v317 和正在进行的发布修订；本文件不是新算法迭代，也不是新留出评测结果。

**当前能确认：80 个真实小改动的实现阶段已经完成，多个维度有明确且限定范围的收益；旧最终留出没有证明新自动调度优于简单策略，“本轮各维度进步均已充分验收”还不能据现有证据宣布。实际跨模型实验和完整累计研发成本仍缺失。** 这些判断分别对应不同层次，不能用其中一个替代另一个。

本审计只读取公开报告、记录、源码快照的文件内容与哈希、冻结清单及已经公开的旧评测结果，没有读取任何私有随机种子，没有运行新留出题，没有修改历史目录或算法。审计时新发布版独立留出尚无结果，下面不预判修订成功。本轮用户要求“依据指导报告进行 80 个真实小迭代、各维度进步”的工作口径来自本审计任务指派；可直接核验的书面约定为下列文件，不把审计者新设的门槛冒充用户原话。

## 3. “各维度进步”实际已经支持到哪一步

为避免旧报告把若干维度合并后造成遗漏，此处按 RUN_PLAN 拆开列示。

| 维度 | 可确认的具体进步 | 仍需区分的缺口 |
|---|---|---|
| 原题认证精度 | 固定候选的完整谱宽约 `1.87189e-8 → 3.88892e-9`，约 4.81 倍；额外残差修正例约 `3.26250e-10`；开发高精度参数有完整证书 | 精度比不是速度比；未证明所有势、参数和目标都达标。负阶跃谱 `1e-8` 目标未达；`-3/8`、幅度 `-1/2` 的完整区间仍约 0.04388 |
| 证据可靠性 | 无效输入预先拒绝、严格绑定目标、完整条件和证据树检查、篡改拒绝能力增加 | 新旧留出误接受数同为零，支持该探针集不退步；不能定量声称全局可靠性更高，不能替代全部数学证明 |
| 自动研究动作选择 | 自动规划次数/分区/精度；诊断核心、外围、舍入及内外残差；自动比较路线并保留有效回退 | 能自动行动不等于行动选择有净收益。旧留出成功数不增且比固定递增慢；尚未证实自动诊断与调度总体值得其开销 |
| 新输入适用范围 | 从旧固定奇异指数扩到满足稳定性前提的其他精确参数点；旧独立留出 6/6，未逐题人工改规则 | 已知函数族内部新参数证据，未测新几何或新数学结构；旧三基线也 6/6，因此不能说成功率相对基线提高。单点认证不等于连续参数范围统一谱界 |
| 执行时间 | [同结果性能数据](../geometry_strategy_v238_v317/metrics/equivalent_benchmark.json)在预热、串行、排除导入条件下，三个组件证书精确一致且约快 1.26–2.01 倍，每侧 21 次样本 | 不能推广到冷启动、端到端自动研究或所有任务。旧留出新服务 CPU 比固定递增多约 62.58%；这个实际退步是当前修订应解决的证据缺口 |
| 运算量与表示规模 | 唯一矩减少，四点评价的完整检查 4→1；相同逼近精度用 749 个系数位置，低于此前高精度配置的 1009 | 操作次数、系数位置、CPU、内存是不同指标；不能互换。另一个 v267 对照是 807→749，比较对象不同，不能混用。最小化限于配置的有限候选族 |
| 交互文本成本 | 12 次无补读脚本交互相对合理精简基线，可见编码量约少 2.85% / 3.47%；完整文本及补读计数保存 | 单次收益为零；每次补读时比例很小。没有模型理解率、输入/输出/推理实际用量或自主做题成本数据；不能把文本收益写成模型成本收益 |
| 接口可用性 | 统一入口、摘要/完整视图、批处理、检索与核验、失败隔离均有运行检查 | 程序可调用和健壮性有证据，真实用户完成任务的效率尚未测量 |
| 可复现性 | 按轮保存源码、证据和比较；最终入口和环境说明、快照补跑、冻结文件绑定均可追查 | 历史依赖未完整封存，完整搜索与研发环境不可据此逐时刻重建；不应声称完整封闭复现或完整成本重现 |

“各个维度都有进步”不等于“每一维在每个输入上严格获胜”。原报告没有提出后者；例如基线在某些常数题已经有零误差，可靠性探针已零误接受，再要求这些值逐题严格下降就无意义。更合理且忠于原要求的验收方式，是事先确定任务范围、各维度指标与合理对照，逐项提供可重复的改善证据，同时显示持平、失败和退步。

但不能走到相反极端：仅挑选每维一个有利例子，就把“各维度进步”包装成广泛或稳定优势。当前表里**自动调度的端到端净收益仍未通过旧独立评测**；真实模型成本、广泛迁移和真实使用效果属于未测领域。若完成声明涵盖这些领域，现有证据仍不够。新增局部实验也不能自动扩大结论范围。

## 4. 旧留出结论不能被重新命名

本次直接从[旧留出原始结果](../geometry_strategy_v238_v317/evaluation/holdout_comparison_20260918T193409761871Z.json)核对：

| 系统 | 达标 | 计入的总 CPU 秒 | 误接受/攻击 |
|---|---:|---:|---:|
| 旧默认 | 6/6 | 0.272735 | 0/7 |
| 固定递增 | 6/6 | 0.013863 | 0/7 |
| 验证集统一选择固定配置 | 6/6 | 0.134739 | 0/7 |
| 冻结 v317 新服务 | 6/6 | 0.022538 | 0/7 |

旧试验的 +1 成功收益未出现；同成功数少 20% CPU 的收益也未出现。新服务与最有效的这个简单基线相比更慢，不能删掉该基线后以旧默认为唯一参照宣布整体提速。这个结论基于一次小样本、同进程交错实验，不构成稳定慢 62.58% 的总体估计；它足以否定“这次独立试验已显示速度收益”的表述。

同样成功数也不表示其他维度完全没有改善，例如返回区间可能不同；但这些差异须以预先规定的目标和相应成本分别评价，不能事后拿多算出的精度抵销原定成本门槛。旧成功条件是共同目标容差，不要求所有系统输出完全相同的区间。专门的“同证书”组件实验回答另一问题。

旧六题已用于定位发布修订弱点，今后属于开发/回归材料。发布修订应遵照 PLAN：保留原数据和原失败、先冻结新实现及新规则、后生成未用的新题，并分别报告新旧结果。旧试验的 20% 是有效的历史判定规则；未来可有更合适的规则，但须在看结果之前说明改变原因，不能用于追溯改判。

## 5. 完整研发成本能否从当前证据重建

**不能完整重建。** 当前公开工件足以重新计算部分已记录实验的工具时间、尝试次数、配置选择成本和脚本可见文本编码量；没有覆盖全部研发、失败会话、模型推理、人工和长期维护的完整账目。`recorded_at`、最终测试耗时或某次评测的毫秒数不等于全程研发墙钟，也不能推算总模型 token 或费用。

| 成本项 | 现有可用材料 | 审计判断 |
|---|---|---|
| 旧留出求解、证书重放、错误证书检查 | 原始 rows、attempts、runtime_resources | 可以核对该次纳入统计的本进程 CPU 与墙钟，失败/尝试随结果保存；不含全部外部成本 |
| 固定配置选择 | 5 道验证题×3 配置与选择引用，相关 CPU/墙钟分配到该基线 | 此次实验的准备成本有记录；不是整个算法开发的准备成本 |
| 组件同结果微基准 | 环境、冷暖范围、逐次样本及中位数 | 可复算保存的计时统计，不证明独占机器或总体端到端净收益 |
| 摘要交互与补读 | TOKEN_COMPARISON 和 CONVERSATION_TEXT，编码器版本 | 可重建指定脚本可见文本计数；API 框架、隐藏推理和模型实际账单缺失 |
| 所有 agent 设计、代码、审查、连接失败与重试 | 零散每轮记录与报告中的失败说明 | 不能据这些工件完整逐代理核算；未记录部分不得填零或以平均值伪装实测 |
| 首次研究、人工参与、硬件/内存、长期维护 | 部分环境信息；人工和峰值内存等缺失 | 不能重建完整累计成本或每次成功的长期摊销成本 |

指导报告第 14 节同时要求记录成本并明确“无法取得的数据记为未知”。所以**诚实标注未知符合缺失数据处理规则，但不等于完成了成本测量要求**。缺失不会取消已证实的数学或组件效果；它会阻止“总研发成本下降”“弱模型整体更便宜”“复用已抵消维护成本”等主张。若外部还有完整服务账单和代理事件记录，可以另外核对补充；本审计既未获得也不假定它们存在，不把没有查到说成原则上永远不可恢复。

本地评测程序 `external_model_calls:0` 仅表示那些程序没有调用模型。开发者和并行 agent 已经参与研发，其用量不是零。后续新评测可以把新的准备、初始化、求解、重放、补读等实际成本记录齐全，却不能追溯补造过去未收集的真实账单。

## 6. 未做长期模型实验与本轮完成的关系

指导报告第 1、13、16 节给出明确层次：工具价值、迁移、跨模型优势逐级建立；完整比较“可以分阶段做”，长时间挑战应在小规模实验确认稳定价值后开展。RUN_PLAN 则明确本轮先测本地工具，真实跨模型推理表现单列尚未测量。因此：

1. **80 个真实实现小迭代完成**不以同一轮开展半小时/八小时挑战为必要条件。把长期实验突然加成本轮编号验收条件，没有现有计划依据。
2. **“低成本模型+工具超过强模型”完全未被本轮证实。** 本地纯程序比较甚至还没有测量“同一模型加新工具是否更容易完成”的模型层效果；不能把纯程序策略自动等同于报告第一步的真实模型工具价值试验。
3. **长期目标仍保留为未完成研究目标。** 将本轮工程阶段与长期目标分开，是按原报告阶段设计解释证据，不是降低长期目标。反之，若用户要求的某次具体 goal 明文把实际模型对照也列为当轮必做，阶段性计划不能擅自豁免它；本次可读文件并无这种当轮实验条款。
4. 没有模型的实际版本、相关任务基线、资料权限、预算、工具条件、成功与失败记录，不能判断谁“更弱”或计算跨模型优势。30 分钟成功与另一系统 8 小时未完成，即使将来出现，也不能计算精确 16 倍解题加速，因为后者完成时间仍未知。

同理，形式化证明、跨新几何结构、所有十二个想法以及学术原创性鉴定不是这 80 轮自动附带的完成项；尚未进行就保持未进行，不因为本轮不强制而把它们写成已做到。

## 7. 发布修订的最终验收应怎样下结论

当前状态应保留为：**80 轮实现完成；旧验收中的端到端自动调度净收益缺口仍在；其他维度具有表列限定证据和未测边界；新发布修订的独立结果待审。** 旧 VALIDATION 的 `implementation_complete:true` 与 `goal_all_dimensions_proven_improved:false` 可以同时成立，不能只引用其中一个字段。

后续核验时至少分别回答这些已经有依据的要求：

- 修订是否保留原函数、空间、目标容差、完整谱覆盖与证书重放，没有通过删检查、放宽目标或剔除失败制造收益；正确性和集成检查是否仍通过。
- 修订是否在预先固定的任务和评价指标上，相对于合理简单基线及冻结 v317 消除了所针对的真实退步；初始化、在线、核验、补读、准备和冷暖条件是否单列，失败和高精度样例是否保留。
