# 以算法放大模型的数学研究能力

长期研究指导报告

从几何分析工具出发，探索低成本模型取得高可信、高效率数学进展的路径。

2026 年 9 月 18 日 · 战略基线 1.0

**核心愿景**

通过持续研发可复用的数学算法，让较低成本、较弱基线能力的模型，在明确的任务与资源条件下，完成较强模型在更大预算下仍未完成的数学任务。

“5.6 在半小时内完成 Astra 八小时未完成的任务”作为长期挑战目标保留。它目前尚未得到实测支持，也不构成对任何模型绝对能力的判断。

**长期应坚持的三件事**

- 用可复核的数学进展衡量成果。
- 用未参与开发的题目检验可复用性。
- 用全部研究成本检验效率优势。

## 导读｜以后如何使用这份报告

这份报告用于选择研究方向、设计实验、判断是否继续投入，以及向后续协作者交接。它给出决策原则和研究假设，不预先锁定完整实现。

**最重要的判断是：当前工具已经证明某些计算有效，尚未证明自动研究决策有效。** 函数奇异结构的识别、试探空间的选择和路线切换仍主要由开发者完成。下一阶段应检验这些决策能否被工具承担，并在新题上产生净收益。[P1–P4]

建议保留四条可竞争的战略路线：自动寻找数学表示；从失败中发现辅助引理；构建可迁移的问题族知识；自动发现可复用的研究工具。根据真实瓶颈选择路线，只有衔接反复产生收益时才将其固化。

**使用原则：** 每轮开始只选择一个主要研究假设，注明预期收益、可能失败的原因及对照方法。每轮结束保留失败与负收益，并更新下一次决策。版本号用于追踪变更，不能代替数学或实验成果。

文中 [P] 为项目证据，[R] 为已有论文和项目资料，末尾给出来源。事实、框架建议和未验证假设分别表述。该报告允许随证据修订；修订时应保留改变判断的原因。

## 1｜目标：让算法成为模型的能力放大器

长期目标的主体是“模型与工具构成的系统”。可复用算法能够提供精确计算、有效表示、证明策略或已认证知识，使模型把有限推理投入到真正需要判断的地方。

“较弱”“较强”应由固定配置在相关基线任务上的表现确定；“低成本”应由实际资源账目确定。二者并不天然相同。报告沿用用户的 5.6 与 Astra 称呼作为愿景锚点，正式实验应记录具体模型版本及设置。

### 三层成功

1. **工具价值：** 同一模型、同一原题、相同验收标准下，新工具稳定优于旧工具或合理的常规工具。
2. **迁移能力：** 策略冻结后，在未参与开发的实例和问题族中，仍能减少达到可信目标的总成本。
3. **跨模型优势：** 较低成本模型加新工具，在预先固定的任务组与预算内，优于较强模型加合理常规工具。强模型加新工具的结果同时用于判断工具是否普遍有益。

第三层是最终挑战，前两层提供归因依据。一个工具即使没有达到挑战目标，只要前两层成立，也可能具有独立价值；不能因此把原始挑战宣布为已经实现。

### “做不到”的实验含义

应表述为“某系统在指定题目、配置和预算内未通过验收”。若低成本模型 30 分钟成功、强模型 8 小时超时，不能据此声称强模型永远做不到，也不能把超时当成它的实际解题时长，计算一个精确加速倍数。

算法研发阶段可以使用强模型和人工研究。低成本模型的独立评测阶段若调用强模型协助，必须单列为另一系统；提前研发投入、题目专用知识及人工干预也要计入账目。

## 2｜事实基线：已经获得什么，距离目标还有什么

当前成果集中于单位球面的谱界、函数逼近与相关不等式工具。最新精度例使用负奇异势 q(z)=−|z|^(−1/4)，目标是完整零均值空间中的最低谱值区间。[P1]

| 已有证据 | 正确解释 |
|---|---|
| 10 项分数幂试探，谱区间宽度约 1.00839×10⁻¹⁰ | 固定原题的结构适配与认证有效 |
| 16 项试探，宽度约 1.14556×10⁻¹⁸ | 有精确有理证书；不是任意势的通用精度能力 |
| 98 项测试通过，66 条唯一数学记录重放通过 | 是实现及证书检查；66 条包含嵌套记录，不是 66 道独立题 |
| 直接矩路线：跳跃势约 9.58×10⁻⁶，负奇异势约 1.40×10⁻⁴ | 这条路线单独仍未达到 10⁻⁸ 目标 |
| 历史冻结文件 1071 个未变 | 支持已有证据的可追溯性，不证明数学首创 |

函数本身的 L² 逼近误差、原算子的谱区间宽度和试探函数的完整残差是不同量，不能互相替代。此前约 1627 倍、135 倍及 1.35 亿倍改善均为指定内部对照下的区间宽度比，不是模型速度比、token 比或对成熟方法的最优性结论。[P1–P3]

**验证边界：** 当前使用自有精确有理验证器，未接入形式化证明助手。16 项候选的证书已重放；另一路“合并整个 Hu 后直接积分”的额外交叉核验尚未执行。最新验收重放了证据，没有重新运行候选优化搜索。[P2、P3]

旧 token 实验测量的是公开词表对可见文本的编码长度。相对完整文件节省约 93.6%，但相对精简基线仅约 18.4% / 15.4%；另有小题组增加约 11.2% / 18.9%。这些结果不足以推断真实推理消耗。尚无真实跨模型、半小时／八小时时限或压缩回执理解率实验；开发过程本身当然消耗了模型资源。[P4、P5]

## 3｜为什么可能获得显著优势

下面是待检验的提效机制。它们具有不同的收益来源，应分别归因。

**减少需要搜索的数学空间。** 合适的坐标、函数族、对称性分解或问题改写，可能把高维试错转成少量有效选择。当前分数幂案例支持这种机制在特定题目上有效；自动发现它的能力仍待验证。

**把反复推理转成可靠操作。** 精确积分、谱尾比较、区间排除等重复工作可由程序承担。模型主要负责提出假设、选择方向和补充缺失结构。工具本身的计算与验证成本必须计入。

**直接修复阻碍证明的缺口。** 候选已经准确时，继续优化候选可能收益很小；寻找谱隙、尾部或紧性方面的辅助结论，可能更有效。关键假设是能找到足以推进原题且更便宜的中间问题。

**让一次研究服务多次任务。** 代表问题、可迁移引理和带条件的模型能够降低后续成本。这里的优势依赖任务分布及复用次数，不能与首次面对新题的能力混合报告。

**从研究经验中产生新操作。** 若多个任务反复出现相同瓶颈，可以尝试搜索或提炼一个通用算法。它应在冻结后的新题上有效，才能成为工具，而不只是开发题的答案包装。

一个可复用数学工具应具有：明确输入、适用条件、数学动作、输出证据、已知失效情形和使用成本。工具可以是一条辅助界、一种表示生成规则、一种结论运输方法，或一项有实测收益的研究调度策略。

共同的失败条件是：识别、试探、检索或认证的开销超过节省；收益依赖逐题手工补答案；原问题在转换中被悄悄简化。这些条件必须能够触发撤销决策。

## 4｜四条战略路线：根据瓶颈选择

| 路线 | 核心研究对象 | 值得投入的信号 | 应转向的信号 |
|---|---|---|---|
| A 自动寻找表示 | 坐标、函数族、分区、局部展开与问题改写 | 奇点、多尺度或不适合的基限制了精度 | 每题都要手工给关键项；试探成本抵消收益 |
| B 发现辅助引理 | 能消除认证瓶颈的中间结论 | 候选稳定，但间隙、尾界或覆盖条件不足 | 子引理等同或难于原题；出现循环依赖 |
| C 迁移问题族知识 | 代表问题、参数范围和可靠运输关系 | 大量任务结构相近，已有结论可复用 | 迁移范围太窄；跨退化点失效；维护成本高 |
| D 发现研究工具 | 生成表示、构造证书、选择动作的小算法 | 重复动作与验收器已经稳定 | 只对训练案例高分，或利用评估漏洞 |

路线 A 可借鉴 Chebfun 的表示管理与 AlphaGeometry 的数学动作；B 可借鉴 ReProver 的证明状态、引理分解及 AlphaProof 的邻近题研究；C 对应 pyMOR 的离线／在线思路；D 可参考 FunSearch、AlphaEvolve 和 ShinkaEvolve。[R1–R11]

这些路线允许竞争和切换。例如 A 获得好候选后转入 B；B 形成稳定引理后成为 C 的资产。只有这种衔接在多个案例中重复有效，才值得构建自动连接。

当前项目可先以 A 和 B 的小范围比较为主要候选，因为已有案例同时暴露了表示误差与认证瓶颈。这是依据现有证据的暂定倾向。若未来主要需求变成重复求解参数族，C 可能更合适；验收尚不稳定时，D 不宜先行扩大。

第一阶段继续用几何谱与不等式估计作为可量化试验田。其结果只支持相应范围，不能推出工具已具备整个几何领域的通用研究能力。

## 5｜继续保留的想法库

以下方向用于提出下一轮假设，并不要求全部实现。

| 研究动作 | 几何研究中的例子 | 值得检验的收益与主要障碍 |
|---|---|---|
| 换一种数学表述 | 不等式转为算子正性或变分界 | 可大幅缩小搜索；必须保存转换条件 |
| 从方程生成表示 | 从奇异势推导候选幂次 | 少量结构项可能提高精度；局部正确不保证全域有效 |
| 从完整残差产生修正 | 经平滑或预条件生成新方向 | 纠正遗漏结构；原始残差未必属于所需定义域 |
| 倒推缺失引理 | 为已有近似寻找第二谱值下界 | 明确下一研究目标；引理可能并不更容易 |
| 搜索反例与必要条件 | 尖峰势、薄颈或高频序列 | 揭示信息不足；未找到反例不等于成立 |
| 搜索全局证书 | 对偶见证、校准形式或区域排除 | 一份证据约束大量竞争者；可搜索证书类可能不够强 |
| 沿可解几何变形 | 从球面或圆盘逐步走向目标 | 复用已有结论；谱交叉、退化与累积误差会阻断 |
| 研究退化极限 | 分析细管、集中与塌缩 | 识别主导尺度；需要返回有限参数问题的余项 |
| 选择判别性实验 | 区分表示不足与尾界过粗 | 减少盲目加算力；诊断本身可能昂贵 |
| 发现少数关键几何量 | 寻找控制谱量的结构组合 | 降低问题维数；经验相关需要进一步证明 |
| 搜索证明的分解方式 | 普通区域粗估，临界区域精算 | 降低完整证明成本；必须覆盖全部情况 |
| 从记录提炼新工具 | 将重复有效的变换变成带条件操作 | 长期积累能力；需防止把单题技巧过度推广 |

其中等价改写、反例引导、校准和数据引导数学直觉都有既有研究基础。[R12–R15] 本项目的潜在研究价值在于这些动作如何被可靠地选择、衔接和迁移，不能仅因换了系统名称就主张原创。

## 6｜已有框架：分别借鉴其擅长的部分

| 项目 | 实际机制 | 对本项目的参考与边界 |
|---|---|---|
| AlphaGeometry / AG2 | 模型提出辅助构造，DDAR 推导并组织证明 | 借鉴数学动作与状态图；平面几何语言不能直接覆盖分析问题；AG2 公布的主要是符号核心 [R1] |
| LeanDojo / ReProver | 检索前提、生成步骤、搜索分支、Lean 反馈 | 借鉴检索、去重和预算；已形式化命题仍需忠实对应原题 [R2] |
| DeepSeek-Prover-V2 | 拆分子引理，递归完成后组合证明 | 借鉴规划与执行分工；相关方法主要见训练流程，官方材料不等于完整流水线开源 [R3] |
| AlphaProof | 在目标题附近构造课程并继续学习 | 借鉴卡住后的邻近题探索；原系统训练投入大，未完整开源 [R4] |
| FunSearch | 程序群体、模型修改、评估与档案 | 搜索生成规则；公开的是部分核心，评估通过不保证最优 [R5] |
| AlphaEvolve | 多层级代码进化、分级评估与多指标档案 | 搜索算法也可成为对象；官方结果仓库不包含完整系统 [R6] |
| ShinkaEvolve | 分群、修改与交叉、模型选择、经验总结 | 借鉴多路线与成本反馈；档案判重不是学术查新 [R7] |
| Chebfun / Spherefun | 自适应函数表示、奇点处理与球面结构 | 是表示层强参考；数值解析度不自动等于严格证书 [R8] |
| pyMOR | 统一模型抽象、误差驱动降阶、离线／在线复用 | 借鉴跨参数资产；降阶误差不等于原问题全部误差 [R9] |
| IntervalRootFinding.jl | 区域搜索与区间判定分开，保留 unknown | 借鉴搜索权与证明判定的分工；无限维覆盖需额外论证 [R10] |
| LeanEuclid | 文本形式化、图形推理、命题语义对照 | 借鉴原题一致性；外部 SMT 引入的信任边界需明确 [R11] |

这些项目分别支持了架构中的某些机制。它们的组合是否产生额外价值，仍需与直接使用成熟工具比较。公开权重、论文伪代码、结果验证代码和完整运行系统是不同的公开程度。

## 7｜概念框架：保存研究对象及其数学关系

一个有指导价值的组织方式，是维护“带证据关系的研究图”。节点可以是原问题、候选表示、辅助引理、参数区域、局部极限或证书；边必须标明它们之间的数学关系。

**等价、蕴含、给上界、给下界、带余项近似、未经验证的启发**应是不同关系。原问题及约束保持固定，变换生成新节点。节点看起来更容易或数值更漂亮，都不能自动替代原题。

### 研究循环

固定原题与验收 → 分析可靠事实和缺口 → 提出少量数学动作 → 小预算试探 → 检查适用条件与证据 → 保留、切换或停止 → 更新可复用知识。

### 五项职责

- **原题管理：** 保存几何、定义域、边界、函数空间、目标、假设和验收标准。
- **策略提出：** 模型或规则产生表示、实验、辅助引理及替代路线。
- **计算执行：** 数值、符号、精确算术等工具生成候选和中间量。
- **证据检查：** 核对原题绑定、条件、覆盖范围和声称的结论强度。
- **经验复用：** 保存成功条件、失败类型、实际成本和可迁移范围。

这些是逻辑职责，不要求立即建设五个独立子系统。模型可以影响搜索顺序，但不能靠自述改变一个结论的证据状态。

失败记录应区分：实现错误；预算不足；当前方法太弱；原题信息不足；已认证反例；尚未知的数学缺口。只有合法分解存在时才报告误差分量，否则将瓶颈判断标成待检验假设。

## 8｜评测：怎样证明工具带来了优势

实验前固定原题、信息权限、成功标准、预算、模型与工具版本。强模型应拥有合理的编程、文献检索、数值和符号工具；“只准大模型裸推理”可作为诊断组，不能成为唯一主要基线。

| 系统 | 常规工具 | 旧项目工具 | 新框架工具 |
|---|---|---|---|
| 较低成本模型 L | 基线 | 版本对照 | 目标系统 |
| 较强模型 H | 跨模型主要基线 | 归因对照 | 工具普适性与能力上限参考 |
| 无 LLM 的固定／自适应策略 | 适用时加入 | 自动化基线 | 判断模型决策是否有净收益 |

完整矩阵可以分阶段执行，但发布某种结论前，必须补齐支持该结论的对照。若无模型策略同样有效，应简化系统，算法贡献仍然成立。

主指标是**给定预算内达到认证目标的成功率**，辅以达到目标所需时间、费用及其分布。等时间与等费用比较分别报告；并发、硬件和总计算量也要记录。失败和超时不能从统计中删除。

### 试验纪律

- 采用同题成对比较；随机系统重复运行，报告分布和适当的不确定性，避免只取最好一次。
- 预先定义何为实用改善，不能看见结果后选择门槛。小样本只形成初步证据。
- 用消融实验移除结构生成、残差反馈、检索或模型决策，确认真正的收益来源。
- 工具组获得的预制模板、证明和提示全部登记；禁止针对最终测试题临时注入答案。
- 模型或工具重大变更后，重建相关基线。旧版本成绩不能自动移植给新版本。

30 分钟／8 小时挑战应在较小规模对照已经显示价值后再投入，并预先规定任务组及资源条件。一次成功故事不足以证明稳定能力优势。

## 9｜题目与验收：让进展对应真正的数学目标

题目分成开发集、用于选择策略的验证集、冻结的最终测试集。结构相近的参数变体用于检查局部迁移，整类未见问题用于检查更广的泛化，二者分开统计。公开题的训练污染通常难以完全排除，应记录来源与已知风险，不宣称无法证明的“绝对未见”。最终测试结果一旦用于选择策略或定位弱点，该题集即成为开发资料；下一次泛化结论须使用新的独立留出集。

### 三类任务各自验收

| 任务 | 完成标准 | 容易混淆的中间结果 |
|---|---|---|
| 精度任务 | 原题目标量具有指定宽度的有效区间或指定误差证书 | 拟合很好、投影残差小、某个扇区达标 |
| 证明任务 | 完整证明，或事先约定且确能推进原题的关键引理 | 自然语言论证流畅、形式化了较弱命题 |
| 探索任务 | 经复核的反例、改进界、有效构造或可迁移方法 | 数值疑似反例、未证明的经验规律 |

可用已解困难题检验方法发现，再用已知状态明确的开放问题检验有价值的局部进展。开放问题的状态需要引用当时文献；当前固定奇异势算例属于开发与校准案例，不包装成解决重大开放问题。

暂无廉价自动评分器的引理发现与概念探索，仍属于长期范围。可用阶段性证据和人工复核判断价值，不因暂时无法标量评分就排除方向；正式能力主张仍需事先明确验收。

**全局最优的含义必须绑定目标与可行域。** 在固定函数族中最优，不等于对全部允许函数最优；找到最好的已知候选，不等于证明没有更好对象。区间覆盖、谱尾、退化情形和原始约束必须进入相应论证。

证据可分别标记为：启发式猜测、数值支持、自有验证器认证、形式化证明。它们回答不同问题。形式系统中的结论也只对已编码的假设和命题负责，原题语义检查仍是必要环节。

最终关键结果应尽可能由未参与候选搜索的检查路径复核；若生成与检查共享公式或代码，应记录这种依赖，不能称作完全独立。

## 10｜成本与 token：优化完整过程

应同时维护三本账：首次解决一个新问题的成本；已有资产服务后续问题的边际成本；包含研发、训练、维护的累计成本。对于同一问题族，可报告：

**每题平均总成本 =（离线准备成本 + 全部在线求解成本 + 维护成本）÷ 已处理题数。**

这项均值必须与成功率、失败次数一起报告；若另报每个成功任务成本，也要把失败消耗计入分子。只有在实际需求分布和合理复用次数下划算，离线准备才构成实用优势。

### token 与计算应分开记录

- 模型服务实际报告的输入、输出、缓存及可获得的推理用量；不可见部分标未知。
- 工具返回文本的大小与词表估算；它们不能冒充真实推理 token。
- 工具执行、验证、检索、失败重试、硬件和墙钟时间。
- 全部并行 agent 的资源与人工参与；不只记录最后成功分支。

节省 token 的优先方向是减少重复探索、复用有条件的数学结论、让常规循环由程序完成。回执压缩应保留目标、条件、界的方向、状态和证据引用；还需测试模型是否正确理解，以及按需取回详情后的总成本。

并行应围绕不同假设、独立审查或有意义的候选路线展开。用户授权的最多 18 个 agent 是上限；并发数量应由任务价值和预算决定。更多并发带来的墙钟缩短，应与总资源变化一同展示。

把成本调度算法本身的试探、记录和维护开销纳入比较。若一个简单固定策略已经足够好，复杂控制器必须提供额外证据证明值得保留。

## 11｜迭代制度：每轮回答一个可检验问题

每轮采用同一研究结构：**真实失败或结构性假设 → 最小改动或实验 → 固定对照 → 复核结果 → 保留／修正／撤销。** 新假设也可以来自数学推导或新文献。用户指定迭代数量时，应先说明各轮要检验什么，避免把参数变化或文档修改等同于新的数学算法。

| 阶段 | 应交付的证据 | 继续条件 | 转向或停止信号 |
|---|---|---|---|
| 可信性 | 原题绑定、有效证书、错误输入识别 | 认证链条与声明一致 | 错误证书：暂停性能宣传，先修复 |
| 单项价值 | 同模型、同信息、同预算对照 | 改善稳定且超过新增开销 | 只赢弱基线或手工案例 |
| 迁移 | 冻结策略后的留出结果 | 新实例或新结构仍有效 | 必须逐题修改关键规则 |
| 跨模型优势 | 固定任务组上的成本与成功率 | 实用优势可重复、可归因 | 多轮无净收益却持续增复杂度 |
| 长期积累 | 后续任务成本与维护账目 | 复用收益超过积累成本 | 档案越大，检索认证越昂贵 |

每轮成功标准应提前确定；数值门槛由预算和实际用途决定，本报告不虚构已经达成的收益指标。

失败之后，先区分实现问题、数学路线问题、信息不足和预算不足。新增工具、增加 agent 或扩大函数族，需要明确的瓶颈证据或可检验的结构性假设。新工具应说明替代或改善了哪个环节，并在独立案例中证明作用。

对于长期无收益的路线，保留有效的负面结论：哪些信息不足、哪类结构会破坏估计、什么成本不可接受。这些可以成为研究资产，但仍需区分已证限制与暂时未成功。

## 12｜原创性与项目定位

当前核心基础包括奇点适配谱基、Temple 残差界、Schur 约化、球面插值及相对二次型方法，均有明确先例。[R16–R20] 现阶段可靠定位是：基于已有数学方法的专用、可复核研究工具原型。[P6]

### 三条证据链分别建立

- **数学贡献：** 新命题、新证明机制或新适用范围；给出严格论证及最接近文献对照。
- **算法贡献：** 新的自动决策能力，或可分析、可实测的成本与可靠性改进。
- **工具价值：** 在相同原题与验收标准下，让模型在留出题中获得更好成功率或更低全部成本。

组合已知方法可能产生很高工具价值，但三种贡献不能互相替代。内部版本数、更多小数位或很大的内部改善倍数，都不足以证明学术原创性。

比较有判别力的原创性候选是：自动从方程生成合法表示；从认证失败提出有用且更便宜的引理；带条件地运输证明；搜索在新题上有效的数学操作。每一项仍需查找近邻工作，不能因当前尚未找到相同实现就宣布首创。

方法先例与代码来源也分别检查。使用已知数学原理不等于抄袭代码，独立编写代码也不等于发明数学方法。发布时保留来源、第三方通知、失败记录、验收范围与可复现入口；本报告不构成穷尽查新或代码原创性鉴定。

模型训练、工具代码和研究资产可能分别有贡献。描述成果时指出实际新增了哪一部分，避免以“AI 数学研究平台”这样的宽泛名称代替可验证内容。

## 13｜后续交接与决策记录

每次继续工作，先阅读本报告的目标、事实基线及最近一次决策记录。保留历史证据，另行保存新实验；更改评估标准时说明原因，不能追溯性地把失败改为成功。

### 每轮必须留下的简短记录

| 字段 | 应写清楚的内容 |
|---|---|
| 原题与验收 | 几何、空间、条件、目标及什么算完成 |
| 当前缺口 | 已证事实与尚未解决部分，诊断是否可靠 |
| 研究假设 | 为什么某项动作可能改善结果 |
| 对照与预算 | 比较谁、信息是否一致、成本如何记录 |
| 结果与证据 | 成功、失败、超时、证书及实际成本 |
| 适用与失效 | 可迁移范围、反例和已知限制 |
| 决策 | 保留、修正、撤销，以及下一项最值得检验的问题 |

### 一项成果何时可以升级

从单题技巧升级为工具，需要明确输入和条件，并通过留出题检验；从工具升级为框架，需要证明其组织方式带来净收益；从框架升级为跨模型能力主张，需要真实模型对照；从工程贡献升级为学术原创主张，需要独立的文献与理论证据。

### 下一阶段保留的三个问题

1. 自动结构生成和完整残差反馈，能否减少达到同一认证精度的总成本？
2. 当精度停滞时，系统能否区分“需要更好的候选”与“需要新的证明条件”？
3. 一次研究留下的操作和结论，能否在不同题目中合法复用，并产生可测量收益？

这三个问题可以分别开展，不要求一次完成全部架构。它们与最终愿景之间的联系，应通过每一阶段的证据逐步建立。
