# C2 完整空间强势扩展：实施前方案

只增加新搜索策略，继续使用旧 `fullspace_m0_fractional_temple_v1` 证书及旧 `fullspace_singular.verify`。范围为负幅度、`-1/2<alpha<0` 的完整空间任务；平均零、阶跃及逼近不由本组件处理。

旧 C 的问题是用径向尾屏障作为候选残差优化的启发参数；虽然从未把它直接签为第二谱值证明，强势例中仍导致反复无用候选、耗尽回退预算。C2 在候选前先用旧已验证 Hölder 型界构造完整比较核，通过少量精确惯性二分取得真实粗第二谱值下界。尾屏障只作为严格正尾约束，绝不当成第二谱值下界。

候选使用这个已验证的粗间隔；必要时另求粗基态下界，为逆迭代提供已验证的较近移位。完整残差平方 `v` 和 Rayleigh 值 `mu` 决定认证需求 `beta >= mu+v/epsilon`，其中先分配 `epsilon=15*tol/16`。粗界足够则直接出旧证书，不足才检查需求阈值；失败必须区分尾屏障不足、惯性方向过多、候选尚未进入间隔和资源不足。保留合法宽证书，不把它算作达标。

实际接口：`solve(task, *, wall_seconds=None, progress=None)` 返回 `certificate`、`certificate_valid`、`target_met`、`status`、`attempts`、`counters`、`stop_reason`、`elapsed_seconds`、`remaining_seconds`、`fallback_recommended` 和具体 `fallback_reason`。只运行本扩展，不隐式调用旧整题求解器；根统一入口决定是否用剩余时间回退。`verify(certificate, task)` 调旧原题绑定验收。

预算从组件入口开始，含延迟导入和输入规范化。按根统一运行时约定，由根把总剩余时间的70%传入，组件不二次预留30%。每个候选有 `min(2秒,组件剩余时间/2)` 的独立硬期限，在独立 Python 子进程中执行并记录启动、传输、失败及终止成本，避免单轮候选吞掉根的回退预算；本进程的型界和惯性步骤仍是协作检查，根的外部硬期限覆盖全部执行。每个顶层动作开始、结束、异常都通过 `progress(dict)` 通知；候选进程CPU单独记录，不能只用父进程CPU忽略它。仅做少量公开新参数功能检查，另保留旧公开失败作回归，不读取旧seed或启动全量性能比较。

实施先验证粗间隔与移位策略是否能产生可接受候选；任何不支持、超时和原验证拒绝都记录具体原因。若近移位没有可靠收益则仅保留已认证粗间隔，不预先声称普遍提速或模型token收益。

## 已实现与功能证据

采用旧 Hölder 型界及完整原始矩核，8步精确惯性二分构造粗第二谱值证书；另外6步构造粗基态下界证书。两者先由旧验证器重放，再传入候选子进程再次检查。逆迭代移位为已证基态下界减去 `1/1024`；每4步用完整强算子残差检查需求，最多24步，之后最多2次残差细化。候选规模按6/10/14/16递增；第二核规模阶段只重试16项，保留每次失败。

候选搜索已在两条公开功能检查中通过：新参数 `q=-(7/3)|z|^(-3/8)+1/5`、axis1，以及旧公开失败 `q=-3|z|^(-2/5)`、axis0，均为完整空间、目标 `1e-8`。后一例仍先发生8次需求阈值超过正尾屏障，核规模从12扩大到16后才获得达标证书，未隐藏这些失败。完整记录和独立旧重放结果见 `FULLSPACE_FUNCTIONAL.json`。这只是功能检查，尚无并列性能结论或新题泛化声明。

组件调用旧 `fullspace_singular.certificate`，它重放gap并重新计算完整残差；为避免在根统一验收前再做一次相同昂贵评估，组件成功时返回 `status=candidate_ready`、`candidate_target_met=true`、`certificate_valid=null`、`verification_pending=true`，并始终将 `target_met` 保持false。根必须执行其独立原题绑定 `assess` 后才能改成最终成功。开放候选为 `certified_candidate_open`，失败和资源停止建议回退并给原因。

`test_fullspace_extension.py` 的11项自测通过，覆盖原题/空间/容差绑定和证书篡改、正尾与完整残差、进度事件、零预算不导入数学、候选硬超时及失败记账、伪造粗间隔拒绝、无隐藏回退、预算不重复预留，以及三项预算中断后的证据保留回归。局部惯性计数排除构造器PSD检查及旧重放内部，不作跨方法总计数比较。所有旧文件保持只读。

## 审查修正与明确限制

独审发现：若已有较好的开放候选，但后续搜索耗尽组件预算，旧实现只在全部循环末尾组装证书，会丢失可恢复结果。现将完整 `powers/coefficients/gap` 在进一步阈值检查前立即保存。预算中断后只允许一次旧证书组装，动作标记 `permit_expired_allocation=true`，全部耗时仍计入组件总时间，外层总硬期限仍有效。这可能使用根预留的部分时间，不能写成组件始终严守其子预算。若恢复组装失败，回执的 `best_candidate` 保留原函数、空间、原精度及完整重建输入，明确要求重新构造与验证，不能直接算成证书。`search_stop_reason` 保留最初预算停止原因，最终状态说明是否保住候选。

候选的2秒上限是墙钟期限，对CPU争用敏感：相同数学工作在其他任务繁忙时可能触发超时，并非CPU工作量恒定的调度保证。根曾在其他代理功能检查可能同时运行时看到E19超预算；当时只保留summary而缺少完整attempt，因此不能认定是具体数学路线、候选硬期限或CPU争用造成。该失败应保留，由安静环境下一次完整progress/response诊断及最终统一10秒测试解释；不因此删除E19、放宽正式预算或声称已解决并发鲁棒性。

预算恢复修正版曾为 `2c4d68f6ccf9ae286f54107980548e5ec4ca460516f33cc96fe33ec7bcc145c4`，其11项自测通过。功能检查的原始计时仅用于追溯执行，不是正式性能对照。
