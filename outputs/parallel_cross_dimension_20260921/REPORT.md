# 同题、跨维度的速度与资源比较

2026-09-21，本地时间。完整运行已经结束，源码冻结与独立结果审计均通过。

**C 是当前普通单点求解的优先选择。B 在批量查询时节省计算，但证明重放和传输成本会削弱收益。A 的新能力主要是负谱结构认证，现有实现不适合作为高精度最低谱求解的通用替代。** 这是对本轮固定公开题目的判断，不是对所有数学问题的排名。

## 1. 比较对象与共同任务

**最低谱值**可理解为数学算子的最低能量。本轮主要任务是在单位球面上，给算子 `−Δ+q` 的最低谱值找到可靠的上下界：`−Δ` 描述函数变化的能量，`q` 是改变各位置能量的势函数。成功要求区间宽度不超过原题指定值。

**证书**保存原题及可核对的数学界限；**完整重放**重新计算、检查证据，不接受求解器自己填写的“成功”状态。**平均零空间**额外要求试验函数在球面上的平均值为零；它与允许全部合适函数的全空间是不同的问题。

本轮修正了上一轮普通接口的比较局限：A、B 上一轮会回退到基线，因此其普通题通过不能说明新路线的能力。这次让 A、B 真正使用各自的新方法：

- A 先运行原生负谱算法，在全部必要证据有效且存在负谱时，提取最低谱的区间；不再调用基线替它完成题目。
- B 先准备预先指定的参数区间证明，再回答同一个查询；单题也完整支付准备费用。原生方法不支持的题明确标出。
- C 直接使用冻结版本，保留其已经实现的条件判断和回退；实际回退逐题记录。
- 基线直接运行原来的算法，作为参照。

原求解器没有修改，新增代码只负责接口与评测。A 会额外计算其他负谱，B 会额外证明连续参数区间；这些额外成果不计作共同最低谱请求的加分，但消耗仍计入。这次测的是用现有整条路线完成共同请求的成本。

## 2. 题目覆盖与达标情况

选了 **16 道最低谱题、2 道函数逼近题**，另有 **2 个参数族，各 16 次查询**。每个设置重复五次，四个系统共完成 360 次冷启动单题、40 个批量会话、640 次批量查询及 640 次独立冷重放。这里的“维度”指评测因素，几何范围仍是单位球面。

下表中“通过”表示五次均在期限内通过完整核验、满足原精度。“精度不足”通常仍有有效区间，只是区间太宽。“未证出”表示没有得到合格证书；它和答出一个错误值不同。

负幂题默认 `q(z)=a|z|^α+b`，z 是球面的一个坐标，默认 `a=−1/2、α=−1/4、b=0`，使用全空间，目标宽度 `10⁻⁶`。表中列出变化项。

| 题号 | 评测因素与原题变化 | 基线 | A 原生 | B 原生 | C |
|---|---|---|---|---|---|
| S01 | 精度放至 10⁻⁴ | 通过 | 通过 | 通过 | 通过 |
| S02 | 默认精度 10⁻⁶ | 通过 | 精度不足 | 通过 | 通过 |
| S03 | 精度收紧至 10⁻⁸ | 通过 | 精度不足 | 通过 | 通过 |
| S04 | 奇异指数 α=−1/6 | 通过 | 精度不足 | 通过 | 通过 |
| S05 | 奇异指数 α=−2/5 | 通过 | 精度不足 | 通过 | 通过 |
| S06 | 接近适用边界，α=−13/27 | 通过 | 精度不足 | 通过 | 通过，回退 |
| S07 | 较弱幅度 a=−1/10 | 通过 | 精度不足 | 通过 | 通过 |
| S08 | 较强幅度 a=−3/2 | 通过 | 精度不足 | 通过 | 通过 |
| S09 | 压力题：a=−3、α=−2/5、精度10⁻⁸ | 未证出 | 未证出 | 准备失败 | 未证出，回退 |

`1_{z≥0}` 在 z≥0 时为 1，否则为 0。最低谱题中，基线与 C 各 **15/16** 稳定达标；A 为 **3/16**，另有 9 道精度不足、3 道投影不支持、1 道未证出；B 为 **8/16**，另有 7 道不支持、1 道准备失败。A、B 的这些比例描述其原生路线覆盖与完成情况，不能解释成它们给出了大量错误答案。

另两道控制题 S17、S18 要求函数的全域 **L² 逼近误差**达标，即平方误差积分后开平方，目标分别为 `10⁻⁶`、`10⁻⁸`。基线和 C 均为 **2/2**，C 使用回退；A、B 原生路线不支持。该组不与谱问题合成一个正确率。

## 3. 单题速度：C 提速，A/B 的专门用途有额外成本

**冷启动**指每次用新进程重新加载程序。单题的 10 秒硬期限覆盖启动、导入、准备、求解、完整验证、数据编码及原始结果落盘。**壁钟时间**是实际等待时间；**CPU 时间**是进程消耗的处理器时间。

在基线与 C 都稳定完成的 15 道谱题上，共各 75 次运行：

| 系统 | 累计壁钟时间 | 累计 CPU 时间 |
|---|---:|---:|
| 基线 | 26.767 秒 | 26.488 秒 |
| C | **19.198 秒** | **18.930 秒** |
| 成本下降 | **28.3%** | **28.5%** |

四个系统都稳定完成的共同单题只有 **S01**，不能用不同的成功子集给三种路线排总名次。S01 的五次中位数如下，均达到同一个 `10⁻⁴` 目标：

| 系统 | 壁钟时间 | CPU 时间 | 峰值内存 | 单份证书体积 | 实际区间宽度 |
|---|---:|---:|---:|---:|---:|
| 基线 | 0.352 秒 | 0.349 秒 | 35.75 MiB | 22.54 KiB | 2.82×10⁻⁸ |
| A | 0.752 秒 | 0.747 秒 | 36.28 MiB | **15.59 KiB** | 6.15×10⁻⁵ |
| B | 0.795 秒 | 0.792 秒 | 36.30 MiB | 57.78 KiB | 7.69×10⁻⁷ |
| C | **0.221 秒** | **0.218 秒** | 35.83 MiB | 19.69 KiB | 9.37×10⁻⁵ |

KiB 为 1024 字节，MiB 为 1024² 字节。内存使用操作系统记录的进程 **峰值 RSS**，即最高驻留内存；它不是只统计数学矩阵的大小。

C 的收益来自减少任务并不要求的精度计算，其区间通常更宽。因此结论是“满足同一要求时更快”，并非所有数值都更精确或所有资源都更少。本题各方法的内存很接近，A 的证书反而最小；计算速度、内存和证书长度不能互相替代。

单点准备 B 在高精度下尤其昂贵：S03 中，B 为整段 `±1%` 幅度区间准备了 **17 个样本、16 个证明单元**，中位耗时 **8.004 秒**、查询证书 **544.90 KiB**；C 用 **0.283 秒**、**19.84 KiB** 的证书完成同一单点精度要求。这个差别说明应根据查询数量决定是否支付整段证明的费用。

## 4. 批量速度：必须把准备与验证放进同一本账

两个参数族均使用 `α=−1/4`、全空间、偏移0、目标宽度 `10⁻⁴`。F1 的幅度区间为 `[-0.505,-0.495]`；F2 扩大为 `[-0.6,-0.4]`。四个系统接收完全相同的 16 个内部查询点，顺序也相同。每个系统在每族的 **80/80 次查询与独立冷重放都达标**。

B 对 F1 用两个样本证明整个连续区间，对 F2 用三个样本；它证明的不只是测试点。表中是五次会话的中位数，包含进程最后退出的成本：

| 参数族 | 系统 | 准备＋16题＋会话内检查 | 再加逐题完整冷重放 | 含冷重放的 CPU 时间 |
|---|---|---:|---:|---:|
| F1 窄区间 | 基线 | 4.113 秒 | 6.084 秒 | 6.026 秒 |
| F1 窄区间 | A | 10.264 秒 | 13.220 秒 | 13.167 秒 |
| F1 窄区间 | B | **0.791 秒** | **3.358 秒** | **3.313 秒** |
| F1 窄区间 | C | 1.967 秒 | 3.938 秒 | 3.890 秒 |
| F2 宽区间 | 基线 | 4.141 秒 | 6.106 秒 | 6.048 秒 |
| F2 宽区间 | A | 9.681 秒 | 12.430 秒 | 12.377 秒 |
| F2 宽区间 | B | **1.136 秒** | 4.041 秒 | 3.993 秒 |
| F2 宽区间 | C | 1.919 秒 | **3.898 秒** | **3.853 秒** |

相对基线，B 在 F1 的会话速度约为 **5.20 倍**，加入逐题冷重放后约为 **1.81 倍**；F2 分别约为 **3.64 倍**和 **1.51 倍**。相对 C，加入冷重放后，B 在 F1 只减少 14.7% 的时间，F2 反而多用 3.6%。这两项都不能按预设的 20% 门槛宣称 B 对 C 有明确加速；五次运行也不足以把几个百分点的差距当成稳定结论。

这些结果支持按实际使用方式选路线：同一已验证会话里做较长参数扫描，B 有明显优势；每个答案都要求独立、无状态地重新核验时，证明库越大，B 的优势越容易被验证成本抵消。第1、4、16题的前缀成本另存于完整结果，没有把 B 的查询阶段单独拿来与基线整次运行相比。

## 5. 内存与传输：B 的时间收益伴随更大的返回数据

下表仍为五次会话的中位数。内存取会话与所有串行重放进程峰值的**最大值**，不把它们相加。返回数据是准备阶段输出加上16份查询响应，包含其中的完整证书；不把评估器日志算作模型要接收的答案。

| F1 | 基线 | 35.92 MiB | 507 KiB |
| F1 | A | 36.52 MiB | 599 KiB |
| F1 | B | 36.45 MiB | 1,017 KiB |
| F1 | C | 36.03 MiB | **398 KiB** |
| F2 | 基线 | 35.92 MiB | 494 KiB |

这些批量题的内存差别很小，没有出现与速度相当的内存下降。B 的返回数据约为 C 的 **2.6 倍、4.0 倍**，原因之一是每条查询都嵌入整份参数证明，便于独立核验。单题的困难设置还会放大资源需求：S06 中 A 的峰值内存约54.14 MiB，却仍未达到目标精度；不能只根据它输出了有效的大证书就记为成功。

本轮程序未调用语言模型 API。**字节数不是 token 数，实际模型 token、代理研发 token、缓存 token 与对应费用均未测量。** 因而不能把上述CPU降幅解释为模型费用降幅。把证明库留在工具侧、让后续查询只传引用，值得作为下一轮独立优化目标；本轮没有实现或给它预记收益。

## 6. 失败原因、验证范围与后续选择

A 的主要问题是区间精度：S02、S03 都停在约 `3.37×10⁻⁵`，S07 为 `1.026×10⁻⁶`，略超 `10⁻⁶`。原算法的计算目标是完整负谱及其和，适配器只是提取最低谱，并未改变有限试验函数集合和搜索策略。若专门优化最低谱，需要另做算法改动，不能靠修改达标阈值来提高本轮成绩。

B 的主要限制是使用范围与准备开销：原生方法只覆盖指定负幂参数族的全空间问题；对阶跃势、平均零空间和函数逼近不支持。更紧的统一精度需要更多样本，增加准备、证书和重放成本。

C 在支持新策略的题上减少辅助计算，对不适用的题回退；S06 就没有得到相对基线的时间收益。保留的强势题 S09 在四个系统下全部未达标，失败记录完整保存。A 在这题快速结束也没有计为速度优势。

独立审计核对了三个解析控制题：S14、S15、S16 的真实最低谱分别为 **−6、+10⁻⁶、−10⁻⁶**。所有40份被判有效的证书均包含解析值并满足原精度。A 在 S15 的五次运行都明确表示投影不支持，没有把零负谱数冒充最低谱值0。

评估器45项合成自检通过；A适配器13项、B适配器7项功能测试通过，另有独立审查。最终前后身份相同，原567个基线文件和上一轮源码保持不变；新快照的604项内容均保全。证书仍依赖共用数学代码，尚不是证明助手中的完整形式化验证。

建议继续以 **C 处理普通单点最低谱，B 处理适合复用证明的参数批量，A 处理负谱个数等结构信息**。接下来优先改善 A 的精度以及 B 的证明引用与重复验证成本，再用没有参与开发的新题检验推广性。本轮并未验证跨模型优势，也没有解决开放猜想的结论。
