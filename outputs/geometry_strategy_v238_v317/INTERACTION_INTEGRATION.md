# 交互计数器的运行时兼容补丁

日期：2026-09-19。此补丁在 v308–317 的十轮记录之后完成，属于集成修复，不新增版本，不修改 80 轮源码快照。

## 原因

原有 `work/token-deps` 中的 `regex/_regex.cpython-39-darwin.so` 和 `tiktoken/_tiktoken.cpython-39-darwin.so` 是 CPython 3.9 二进制扩展。之前交互测试使用本机系统 Python 3.9.6，能够加载；统一测试改用 bundled Python 3.12.14 时，这些二进制不能直接导入。两套解释器都没有另外安装可用的原生 tiktoken 包，原测试因此将可见 token 项跳过。

这是依赖加载问题，没有改变数学证书，也不是编码数量的差异。

## 补丁内容

仅修改 `interaction.py` 的 `offline_text_counter` 依赖加载，并增加一项针对该问题的测试。

1. 使用当前解释器明确支持的扩展文件后缀检查本地二进制是否兼容，避免把 CPython 3.9 扩展直接塞入 3.12 环境。
2. 若当前进程能加载固定版本 `tiktoken==0.11.0`，继续在进程内计数。
3. 否则尝试已经存在的本地 Python，启动隔离的常驻计数子进程。本机实际选中系统 Python 3.9.6；每条文字不再重启解释器。
4. 子进程只接受文字并返回两种编码的整数计数；初始化失败、退出或超时均报错，不用字符数替代。进程结束时清理子进程，也提供显式 `close()`。
5. 两个公开编码文件仍先检查固定 SHA-256，再使用本轮 `token_cache`。不联网、不下载、不安装依赖；不修改冻结目录。加载后恢复调用进程的搜索路径和缓存环境变量。

返回的计数函数增加只读用途的 `measurement_runtime` 信息，区分 `in_process` 与 `local_subprocess`。它描述本地编码运行环境，不是模型身份、模型调用或 API 使用记录。若没有任何兼容的本地解释器与编码依赖，仍明确报告不可测。

- bundled Python：交互测试 31 项全部通过，0 跳过。
- 系统 Python：同一交互测试 31 项全部通过，0 跳过；兼容时仍使用进程内路径。
- bundled Python：整个当前新框架测试目录 196 项全部通过，0 跳过。当次报告为 2.954 秒；此耗时不用于宣称性能改进。
